# บันทึกการทำแผน 2 (db-schema) — ผลลัพธ์ การตัดสินใจ และสิ่งที่ส่งต่อ

## ได้อะไร

- `packages/db-schema`: Drizzle schema สองชุด (SQLite ในเครื่อง · PostgreSQL บนเซิร์ฟเวอร์) 38 ตารางต่อ dialect พร้อมเทสต์ parity ที่เทียบคอลัมน์ · NOT NULL · PK · FK · unique · index · กฎชื่อคอลัมน์ตามหน่วย
- migration: `0000_baseline.sql` ต่อ dialect + migration `--custom` สำหรับ trigger (pg: `server_seq` ขยับตอน UPDATE, ตารางบัญชีห้ามแก้/ลบ · sqlite: ตารางบัญชีห้ามแก้/ลบ) · เทสต์ drift กันแก้ schema โดยไม่ generate
- seed: `seedToRows` + id แบบกำหนดได้จาก natural key (`deterministicSeedId`) · `SEED_TABLES` รายการเดียว · `applySeed*`/`loadCatalog*` ใช้ได้ทั้ง sql.js, sqlite-proxy (async) และ PGlite · ต้นทุน 360 สูตรที่อ่านกลับจาก DB ตรง Excel เป๊ะทั้งสองฐาน
- ข้อกำหนดที่ DB บังคับเอง: เลขบิลไม่ซ้ำต่อเครื่อง · เลขคิวไม่ซ้ำต่อเครื่องต่อวัน · เปิดกะได้ครั้งละหนึ่งต่อเครื่อง · สูตร/BOM ที่ใช้อยู่ได้แถวเดียว · CHECK (ยอดเงินไม่ติดลบ, `VOID_REFUND` ต้องมีบิล ฯลฯ) · ตารางบัญชี (`stock_movement`, `order_event`, `cash_movement`, `z_report`) แก้/ลบไม่ได้

## การตัดสินใจเชิงเทคนิคระหว่างทำ (ไม่ต้องตอบ)

1. เทสต์ฝั่ง SQLite ใช้ **sql.js** แทน better-sqlite3 (build บน Windows เครื่องนี้ไม่ได้)
2. migration ใช้ baseline ไฟล์เดียวเพราะยังไม่มีอะไร deploy — **หลัง deploy ครั้งแรก ต้องต่อท้ายเท่านั้น**
3. `bom.version` / `recipe.version` คือเลขรุ่นของสูตร (แก้ = แถวใหม่) ใช้เป็น `version` ตามข้อ 8 ด้วย — **ไม่ขยับเมื่อ `is_current` เปลี่ยน** การตรวจการเปลี่ยนแปลงต้องใช้ `server_seq` / `updated_at`
4. id ของราคาใน seed ไม่รวม `effective_from` เพื่อให้ id คงที่ข้ามการนำเข้า (ราคาซ้ำ variant+ช่องทางใน seed เดียว = นำเข้าไม่ผ่าน)
5. override `uuid ≥ 11.1.1` และ `esbuild ≥ 0.25` แก้ช่องโหว่จาก dependency ทางอ้อม (exceljs, drizzle-kit)

## ส่งต่อแผน 3 และแผนถัดไป

- แผน 3: ใช้ `deterministicSeedId`, `SEED_TABLES`, `applySeedSqlite`/`loadCatalogSqlite` ผ่าน sqlite-proxy ได้เลย · ต้องเคารพ constraint ใหม่ทั้งหมด (ยกเลิกได้เฉพาะบิลในกะที่เปิด — D47)
- แผน 5 (API): root entry `@dayo/db-schema` เป็น Node + ESM เท่านั้น · SQL ที่เขียนเองต้องครอบ `"user"` / `"order"` ด้วยเครื่องหมายคำพูด · ตาราง T ที่เครื่องต้อง pull มี `server_seq` แล้ว
- ยังไม่ทำ (ตั้งใจ): CHECK ของค่า enum ใน DB (ใช้ชนิด TS + zod แทน) · ตรวจ `device_id` ↔ `chain_id` ใน `verifyChain` (งาน invariant แผน 5/8)
