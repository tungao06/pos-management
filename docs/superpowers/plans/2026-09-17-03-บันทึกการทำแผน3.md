## 3. การตัดสินใจระหว่างทำที่ไม่ได้อยู่ในแผน (รวม CHECK ของ D47 ที่ต้องปรับโค้ดตาม ถ้ามี)
- outbox key `<table>:<id>[:suffix]` แทน `= row id` ของ spec §6.1 เพราะแถว `order` ถูกส่งสองครั้ง (paid, voided) — แผน 5 ต้องใช้รูปแบบนี้ / แก้ spec (M7)
- `order.cost_satang` = Σ(`unit_cost_satang` × qty) ของทุกบรรทัด (T13) ซึ่งอาจต่างจาก single-rounded `needsCostSatang(plan.needs)` ได้ไม่เกิน ½ satang ต่อบิล — ตรงตาม spec (spec นิยามแค่กฎต่อบรรทัด) แต่แผน 7 (รายงาน) ต้องใช้นิยามเดียวกันนี้ (M17)
- D50 ตอบแค่ "เอาตามที่แนะนำ" เป็นภาพรวม — agent เลือกค่าที่เป็นรูปธรรม 4 จุด ที่เจ้าของควรรู้ (รายงานให้เจ้าของแล้วตอน Task 6/8):
  - เพดานล็อก PIN 15 นาที คือค่าสูงสุดของลำดับ 30→60→120→240→480 วินาที ที่ Q3-21 ระบุ (ไม่ได้ระบุเพดานเป็นตัวเลขไว้ตรง ๆ)
  - สีคลื่นใต้แถบบน `#35613B` (เขียวเข้มอ่อนลงจาก `#1E3B22` ของแถบบน) เพื่อให้เห็นคลื่นแยกจากแถบแต่ยังอยู่ในกลุ่มสีเขียว ไม่ใช้ Matcha ตาม Q3-23
  - ป้าย "ยังไม่ส่ง N รายการ" (Q3-26): รายการที่ไม่ใช่บิล (เปิดกะ, เงินเข้า/ออก, stock movement ที่ไม่ผูกกับบิล) นับ 1 ต่อ id เพื่อไม่ให้ป้ายขึ้น 0 ทั้งที่ยังมีของค้างส่ง — เป็นการเลือกวิธีนับที่ทำให้ตัวเลขไม่มีวันเป็น 0 ตอนยังไม่ sync จริง ไม่ใช่นับตามนิยาม "บิล" เดียวกับบิลขาย
  - ตัวนับ PIN ผิด (Q3-21) เก็บใน `sync_state` (แถวในเครื่อง ไม่ sync ไปเซิร์ฟเวอร์ อยู่รอด reload) เพราะ spec ไม่มีตารางสำหรับตัวนับชั่วคราวแบบนี้มาก่อน
- `product.soldOutUntil` มีคอลัมน์อยู่ในสคีมา (จากแผน 2) แต่แผน 3 ไม่มีหน้าจอหรือ endpoint ใดตั้งค่านี้ — ยังไม่ถูกใช้งานในแผนนี้ (เจ้าของรับทราบจาก review ของ Task 8)
