## ส่วนที่เจ้าของต้องทำเอง (agent ไม่เห็นค่าลับ)

| ขั้น | เจ้าของทำอะไร | ผ่านเมื่อ |
|---|---|---|
| 1 | เปิด dayo local (Supabase local + `npm run dev:web` ตั้ง `API_V1_ENABLED=1`, `POS_ORIGINS=http://localhost:4173`) แล้วสร้าง API key ชื่อ "แท็บเล็ตขาย 1" ที่ `/settings/api-clients` (scope `catalog:read staff:read orders:read orders:write`) แล้วนำเข้าแคตตาล็อกจริงของร้าน | มี key ในมือ + แคตตาล็อกจริงขึ้นบน dayo local |
| 2 | รัน `npm run pos:parity` ที่ root ของ repo dayo (commit เดียวกับที่ทดสอบ) ได้ไฟล์ `pos-parity.json` ที่ root ของ dayo (ไฟล์ gitignore ไว้) แล้วคัดลอกไปวางที่ `packages/dayo-pricing/fixtures/pos-parity.json` ของ POS | ไฟล์ถูกวางแล้ว ให้ agent รันเทสต์ต่อได้ |
| 3 | คัดลอกคำตอบจริงของทุกสถานการณ์ใน `CONTRACT_FIXTURE_NAMES` (E1 เปลี่ยน/ไม่เปลี่ยน, E2 ทุกคำตัดสิน, E3, 401/404/429 + หัว CORS) จาก dayo local/`dayo-test` ลง `packages/contracts/fixtures/dayo-api/` (ตัดค่าลับ/กุญแจออกก่อนวาง) | ครบทุกชื่อในรายการ ไม่มีค่าลับติดไปในไฟล์ |
| 4 | ตั้งแท็บเล็ต (เบราว์เซอร์บนเครื่อง dev): กรอก base URL `http://localhost:<พอร์ตของ dev:web>/api/v1` และวางกุญแจเอง (agent ไม่เห็นหน้าจอกรอกกุญแจ) | ตั้งเครื่องสำเร็จ ไม่มีคำเตือน "ตัวคิดราคาไม่ตรง" |
| 5 | เปิด `22 oz` + ตัวแปรบน dayo local ก่อนขายบิลที่ 21; ปิดโปรบนเว็บ **ก่อน** ขายบิลที่ 22 (จงใจให้ยอดไม่ตรงเพื่อทดสอบหน้าเตือน) | ทำตามลำดับที่กำหนดในตารางบิล (ดูหัวข้อ "ขาย 20 บิล" ด้านล่าง) |
| 6 | ขาย 20 บิลตามตารางด้านล่าง (เจ้าของหรือหัวหน้าขายจริงบนแท็บเล็ตที่ตั้งไว้) | ขายครบ 20 บิลตามเคส |
| 7 | เพิกถอนกุญแจบนเว็บ dayo แล้วลองขาย 1 บิล จากนั้นตั้งกุญแจใหม่ที่หน้าสถานะแท็บเล็ต (ใส่ owner PIN) | แท็บเล็ตขึ้น "กุญแจเครื่องถูกยกเลิก" ไม่ใช่ข้อความเน็ตหลุด และบิลที่ค้างถูกส่งหลังตั้งกุญแจใหม่ |
| 8 | เปิด `API_V1_ENABLED=1` ใน production เอง (ไม่ใช่ agent กด) แล้ว deploy POS ตามขั้นตอน devops เดิม | production เปิดใช้งานจริง |
| 9 | กดสำรองข้อมูลภายใน 24 ชม. หลังเปิด production และซ้อมกู้คืนลง `dayo-test` ให้สำเร็จ 1 ครั้ง (แทนการรอสำรองอัตโนมัติ 3 คืน) | กู้คืนสำเร็จ 1 ครั้ง — เงื่อนไขเปิด production ตาม ADR-0048 ข้อ 8 |

## ส่วนที่ agent ทำได้ต่อ (หลังเจ้าของทำขั้นข้างบนแล้ว)

| ขั้น | agent ทำอะไร | ผ่านเมื่อ |
|---|---|---|
| A | ตรวจ fixture ตรงกัน: รัน `pnpm --filter @dayo/contracts fixtures:hashes` ทั้งฝั่ง POS และฝั่ง dayo (อ่านอย่างเดียว) แล้ว diff | diff ว่าง ไม่มี `MISSING`; `pnpm --filter @dayo/contracts test` และ `pnpm --filter @dayo/dayo-mock test` ผ่านกับไฟล์จริง |
| B | อ่าน `pricing.commit` จาก E1 แล้วรัน `vendor:update` + `vendor:check` | `vendor:check` ผ่าน; ถ้า `src/vendor` เปลี่ยน `pnpm turbo run typecheck test` ต้องผ่านโดยไม่แก้ไฟล์สำเนา |
| C | รันเทสต์ parity (`pnpm --filter @dayo/domain test -- parity`) กับไฟล์ `pos-parity.json` ที่เจ้าของวางไว้ | หัว describe ขึ้น "dayo export" และ **ทุกเคสต่าง 0 สตางค์** (เคสที่ล้มเพราะไม่มี `saleTime` หรือแท็บเล็ตสร้างไม่ได้จริง ต้องแยกไว้ให้หัวหน้าอนุมัติ ห้ามแก้เคสเอง) |
| D | ตรวจผลหลังขาย 20 บิล: หน้า "ยอดไม่ตรงระบบกลาง" ต้องว่าง, `select … from orders where source='pos' and pos_computed_total <> total_amount` ต้องได้ 0 แถว (เจ้าของรันคำสั่ง SQL เอง ให้ agent ช่วยอ่านผล) | ตรงตามเกณฑ์ทั้งหมด |
| E | บันทึกผลลง `docs/superpowers/plans/2026-09-25-07-บันทึกเชื่อมจริงก้อน2.md` และ commit ไฟล์ fixture/parity/vendor ที่เปลี่ยน | ไฟล์บันทึกผลครบ (commit ของ dayo, ผล fixtures:hashes ทั้งสองฝั่ง, จำนวนเคส parity ที่ผ่าน, ผล 20 บิล, ปัญหาที่พบ) |

## การทดสอบบนแท็บเล็ตจริง (D51 — ทำท้ายสุดของงานทั้งหมด ไม่ใช่แค่ก้อนนี้)

รายการเช็คที่ค้างไว้จนกว่าจะถึงตอนทดสอบเครื่องจริง (มาจากบันทึกงานของ Task 17/20):

- ตั้งเครื่องด้วยการสแกน QR ของกุญแจ (`BarcodeDetector` บน Chrome Android) ใช้งานได้จริง
- `navigator.storage.persist()` ได้สถานะ "ถาวร" จริงบนแท็บเล็ต
- ขายออฟไลน์จริง (ปิด Wi-Fi) 5 บิล แล้วเปิดเน็ต — บิลส่งครบ
- เปิดสองแท็บพร้อมกัน แล้ว Web Lock `dayo-push` ทำงานถูก (ไม่ส่งซ้ำ)
- ตั้งเวลาเครื่องให้เร็วกว่าจริง 7 นาที — แถบเตือนนาฬิกาขึ้นถูกต้อง ไม่บล็อกการขาย
- ใบเสร็จ/เลขคิวอ่านชัดบนจอแท็บเล็ตจริง (ไม่ใช่จอคอมพิวเตอร์)
- ค้นหาคำว่า `dayo_` ในไฟล์สำรองที่ส่งออกจากแท็บเล็ต — ต้องไม่พบ (กุญแจต้องไม่ติดไปในไฟล์สำรอง)
- **หน้าตั้งเครื่องต้องไม่มีป๊อปอัป "บันทึกรหัสผ่าน" ของเบราว์เซอร์โผล่ขึ้นมา** ตอนกรอกกุญแจ/PIN (พบจากรีวิว Task 17 — เช็คตอนทดสอบเครื่องจริง)
