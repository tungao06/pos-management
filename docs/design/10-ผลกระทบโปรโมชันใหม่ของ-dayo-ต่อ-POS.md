# ผลกระทบของระบบโปรโมชันใหม่ของ dayo ต่อ POS

> ตรวจเมื่อ 29 ก.ย. 2026 · dayo main `dde5ad4` (PR #32–36 · migration 0068–0072 · ADR-0070/0071) · เป็นการอ่านโค้ดเทียบกัน ยังไม่ได้รันเทสต์เทียบราคาจริง

## สรุป

- dayo เปลี่ยนระบบคำนวณโปรโมชันใหม่ทั้งหมด ของเก่าที่ POS ใช้อยู่เป็นแบบเดิม
- ส่วนที่เปลี่ยนมีดังนี้ และทุกข้อมีผลต่อยอดเงิน:
  - โปรเลือกเองโดยพนักงาน
  - กลุ่มโปรและการซ้อนโปร
  - ซื้อ X แถม Y แบบเลือกแก้วถูกสุดหรือแพงสุด
  - ส่วนลดที่ใช้กับตัวเลือกเสริม
  - ปัดเศษลงเป็นบาท และเพดานส่วนลด
  - ช่วงเวลาหลายช่วง รวมช่วงข้ามเที่ยงคืน
- POS ขอเมนูจาก dayo โดยไม่ส่ง `promo_rule_version` จึงยังได้โปรแบบเดิมและ**ไม่พัง**
- **ช่องโหว่คือโปรที่สร้างด้วยความสามารถใหม่ จะไม่ถูกส่งมาที่แท็บเล็ตเลย** และระบบไม่แจ้งเตือนอะไร
  - ตัวอย่าง: โปรที่เลือกตามหมวดหรือขนาด หรือโปรที่มีเพดานส่วนลด
  - ผลคือแท็บเล็ตขายราคาเต็ม แต่ LINE bot ขายราคาลด
- เทสต์เทียบราคาใน POS ยังผ่าน แต่ที่ผ่านเพราะเทียบกับโค้ด dayo ชุดเก่าที่คัดลอกมาไว้ใน POS ไม่ได้พิสูจน์ว่าราคายังตรงกับ dayo ปัจจุบัน
- พบเพิ่ม: เลข commit ของ dayo ที่ POS อ้างไว้ 2 ที่ไม่ตรงกัน
  - `packages/dayo-pricing/VENDOR.json` = `4f35932`
  - `fixtures/pos-parity.json` = `a0f76e2`

## ต้องแก้อะไร (แผนใหม่ ประมาณ 2–4 วันทำงานของ agent)

1. อัปเดตโค้ดคำนวณราคาของ dayo ที่คัดลอกมาไว้ใน `packages/dayo-pricing/src/vendor/` ให้เป็นเวอร์ชัน `dde5ad4`
   - `types.ts`
   - `promotions.ts`
   - `money.ts`
   - เพิ่ม `promoRule.ts`
2. `packages/contracts/src/dayo-api.ts`: schema ของโปรโมชันต้องรับรูปแบบใหม่ ได้แก่ `rule`, `template`, `timeWindows`, `groupCode` และ `promotionGroups`
3. ขอเมนูด้วย `promo_rule_version=1`
4. หน้าขาย: รองรับโปรที่พนักงานเลือกเองพร้อมเหตุผล (`manualPromotionIds`, `manualPromotionReason`) และแสดงส่วนลดแยกตามแก้ว
5. เพิ่มชุดเคสเทียบราคาสำหรับทุกความสามารถใหม่ โดยเทียบกับชุดเคสที่ dayo ทำไว้เองใน `packages/shared/test/fixtures/promo-rules/`
6. แก้เลข commit อ้างอิงให้ตรงกันทั้ง 2 ที่

## ข้อที่ตรวจแล้วไม่ถูก (หมายเหตุ 30 ก.ย. 2026)

ตอนเขียนแผน 10 ตรวจโค้ดอีกรอบ พบว่าบางข้อด้านบนไม่ถูก:

- **"ไม่พัง" (สรุปข้อ 3) ไม่ถูก (F2)** — คำตอบเมนู (E1) ของ dayo ตั้งแต่ migration 0071 มีค่าใหม่ที่เป็นตัวเลขใน `supported_fields` POS อ่านไม่ผ่านทั้งคำตอบ ทำให้อัปเดตเมนูและรายชื่อพนักงานไม่ได้ · แก้แล้วในแผน 10 · ไม่มีผลจริง เพราะยังไม่มีแท็บเล็ตใช้งานจริง (D51)
- **เลข commit `dde5ad4` (F1)** — dayo เดินต่อไปที่ `f4cda56` (มี ADR-0072) · ตอนนี้ตรึงที่ `f4cda56` (D128 แก้ D121)
- **"เลข commit ไม่ตรงกัน 2 ที่" (F9)** — จริงๆ ไม่ตรงกัน **3 ที่**: `VENDOR.json` และ `pos-parity.seed.json` = `4f35932` · `fixtures/pos-parity.json` = `12885fe` · `docs/design/pos-parity.json` (ไม่อยู่ใน git) = `a0f76e2`
- **"ระบบไม่แจ้งเตือนอะไร" ไม่ถูก** — dayo ติดธง `amount_mismatch` ให้บิลของโปรที่จำกัดจำนวนครั้ง และเว็บ dayo แสดงป้ายบอก (D126)
