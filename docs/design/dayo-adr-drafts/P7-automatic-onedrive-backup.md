# ADR-P7 (เลขถัดไปตอนรับเข้า) — สำรองฐานข้อมูลอัตโนมัติทุกคืนไป OneDrive (เพิ่มจากการสำรองแบบกดเอง)

- สถานะ: **เสนอ** · 25 ก.ย. 2569 (ร่างจากทีม POS — สเปก POS §8, เจ้าของตัดสิน Q40, Q41, Q42) · **เพิ่มจาก ADR-0021** (ปุ่มสำรองเองและ Export Excel คงเดิมทุกข้อ) · เคารพ **ADR-0036** (ฟรี ไม่ผูกบัตร ไม่ใช้ R2) · ใช้ช่องแจ้งเตือนของ **ADR-0044**
- บริบท: Supabase ฟรีไม่มีสำรองอัตโนมัติ · ADR-0021 ให้เจ้าของกดดาวน์โหลดเอง ลืมกด = ไม่มีสำรอง (มีแค่ป้ายเตือน 7 วัน) · เมื่อ POS ส่งบิล กะ เงินสด ค่าใช้จ่าย เงินเดือน เข้าฐานนี้ ข้อมูลเงินทั้งหมดของร้านอยู่ที่เดียว การไม่มีสำรองอัตโนมัติเป็นความเสี่ยงหลัก · เจ้าของเลือก (Q24/Q34): GitHub Actions ทุกคืน → `pg_dump` → เข้ารหัสด้วยรหัสที่เจ้าของถือ → อัปโหลด OneDrive ด้วย rclone (แอป Microsoft ของ rclone เอง ไม่ลงทะเบียนแอป ไม่ผูกบัตร) · เก็บ 30 รายวัน + 12 รายเดือน · ล้มต้องแจ้ง · ซ้อมกู้รายเดือน
- ตัดสินใจ:
  1. `.github/workflows/backup.yml` ใน repo นี้ · `schedule: 0 18 * * *` (01:00 ไทย) + `workflow_dispatch` · `permissions: contents: read` · timeout 15 นาที
  2. **ดึง**: `pg_dump --format=custom --no-owner --no-privileges --schema=public --schema=supabase_migrations` ผ่าน **session pooler** ของ Supabase (IPv4 — runner ของ GitHub ต่อ direct connection ที่เป็น IPv6 ไม่ได้) · ติดตั้ง `postgresql-client` รุ่นหลักเดียวกับ Postgres ของโปรเจกต์ (จาก apt ของ PostgreSQL) · role ที่ใช้: `dayo_backup` อ่านอย่างเดียว (SELECT ทุกตาราง/sequence + `BYPASSRLS` เพราะทุกตารางเปิด RLS ไม่มี policy + execute `backup_log_auto`) ถ้า Supabase อนุญาตให้สร้าง role ที่มี `BYPASSRLS` · ไม่อนุญาต = ใช้ `postgres` และบันทึกความเสี่ยงนี้ใน OPERATIONS
  3. **manifest.json**: เวลา · migration ล่าสุด · จำนวนแถวต่อตาราง · `pg_database_size` · sha256 ของ dump
  4. **เข้ารหัส**: `tar` (dump + manifest) → `gpg --batch --symmetric --cipher-algo AES256 --passphrase-file` จาก secret `BACKUP_PASSPHRASE` (Q42: เก็บเป็น GitHub secret เพื่อให้ซ้อมกู้อัตโนมัติได้ · **เจ้าของต้องเก็บสำเนานอก GitHub ด้วย** — เสียบัญชี GitHub แล้วไม่มีสำเนา = เปิดไฟล์สำรองไม่ได้ · SETUP มีขั้นตรวจว่าเจ้าของเก็บสำเนาแล้ว) · ชื่อไฟล์ `DA-YO_db_YYYY-MM-DD.tar.gpg`
  5. **อัปโหลด**: `rclone copy` ไป `onedrive:DAYO/Backups/auto/daily/` · วันที่ 1 ของเดือนคัดลอกไป `auto/monthly/` · ตรวจด้วย `rclone lsjson` ว่าไฟล์อยู่และขนาดตรง · ลบเก่า: daily เก็บ 30 ไฟล์ล่าสุด monthly เก็บ 12 ไฟล์ล่าสุด · config ใน secret `RCLONE_CONF` (เจ้าของรัน `rclone config` ครั้งเดียวบนเครื่องตัวเอง)
  6. **token ของ OneDrive**: rclone ต่ออายุ token ระหว่างรัน แต่ไฟล์ config ใน runner หายไปเมื่อจบงาน · token ใน secret จะหมดอายุ (Microsoft: ไม่ได้ใช้ 90 วัน) แม้รันทุกคืน ถ้าไม่เขียนกลับ → ขั้นท้าย `gh secret set RCLONE_CONF` ด้วย fine-grained PAT สิทธิ์ "Secrets: read and write" เฉพาะ repo นี้ (secret `GH_SECRETS_PAT` · เจ้าของสร้างเอง · workflow เตือนก่อน PAT หมดอายุ 14 วัน) — เจ้าของตัดสิน Q41 · PAT ใกล้หมด/หมดแล้ว หรือเขียนกลับล้ม = 🔴 ใน Discord ช่องระบบ
  7. **บันทึกในระบบ**: `backup_log.kind` เพิ่มค่า `auto` · ฟังก์ชัน `backup_log_auto(p_row_counts jsonb, p_bytes bigint)` (ไม่ผ่าน `dayo_require_staff` · grant ให้ `dayo_backup` เท่านั้น) · "สำรองล่าสุด X วันก่อน" (ADR-0021/0046) และสรุปเช้า (ADR-0044) นับรวมการสำรองอัตโนมัติ
  8. **แจ้งเตือน** (Q40): ขั้น `if: failure()` ส่ง 🔴 ERROR + `@here` เข้า Discord ช่องระบบ `#dayo-ระบบ` (`DISCORD_ALERT_WEBHOOK_URL` เก็บซ้ำใน GitHub secrets) รูปข้อความตาม `discordMessages` (ADR-0044) · อีเมลของ GitHub เมื่อ workflow ล้มเป็นอีกชั้น
  9. **ขนาดฐาน**: เตือน 🟡 เมื่อ `pg_database_size` ≥ 60% ของ 500 MB · 🔴 + `@here` เมื่อ ≥ 80% · รายงานพื้นที่ OneDrive ที่เหลือ (`rclone about`) เตือนเมื่อ < 1 GB
  10. **ซ้อมกู้อัตโนมัติ**: `.github/workflows/restore-test.yml` วันที่ 2 ของทุกเดือน: ดาวน์โหลด daily ล่าสุด → ถอดรหัส → `pg_restore` ลง service container `postgres:<รุ่นเดียวกัน>` → เทียบจำนวนแถวกับ manifest + ผลรวม `total_amount` ต่อเดือน → 📊 ผ่าน / 🔴 ไม่ผ่าน เข้า Discord · OPERATIONS เพิ่มขั้นกู้คืนจริงจากไฟล์นี้ (ต่างจาก `npm run restore` ของไฟล์ zip)
  11. ค่าลับทั้งหมดเจ้าของตั้งใน GitHub เอง: `SUPABASE_DB_URL` `BACKUP_PASSPHRASE` `RCLONE_CONF` `DISCORD_ALERT_WEBHOOK_URL` `GH_SECRETS_PAT` · agent ไม่เห็นค่า · log ของ workflow ห้ามพิมพ์ค่าเหล่านี้ (`::add-mask::`)
- ทางเลือกที่ไม่เลือก: R2 (ต้องผูกบัตร — ADR-0036) · Supabase Pro (เสียเงิน) · สำรองผ่านปุ่มเว็บอัตโนมัติ (ต้องมีคนล็อกอิน) · ลงทะเบียนแอป Azure เอง (ต้องใช้บัตร/บัญชีองค์กร) · เข้ารหัสแบบกุญแจคู่ที่กุญแจลับอยู่นอก GitHub (ซ้อมกู้อัตโนมัติไม่ได้ และ secret DB URL ใน GitHub เข้าถึงฐานได้ทั้งหมดอยู่แล้ว)
- ผลที่ตามมา: `.github/workflows/{backup,restore-test}.yml` · migration (role `dayo_backup` ถ้าทำได้ · `backup_log.kind` · `backup_log_auto`) · SETUP (ขั้นเจ้าของ: `rclone config`, PAT, ใส่ secret, สร้าง role) · OPERATIONS (ขั้นกู้จาก dump · ตรวจ Discord ทุกเช้า) · ADR-0021 ข้อ "ผลที่ตามมา: ลบ backup.yml" ไม่ใช้แล้ว (workflow กลับมาแบบไม่มี R2) · GitHub Actions ~100 นาที/เดือน (ฟรี 2,000) · OneDrive ฟรี 5 GB พอราว 1–2 ปีแรก (ดูสเปก POS §10.4)
