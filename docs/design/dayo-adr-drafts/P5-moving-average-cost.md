# ADR-P5 (เลขถัดไปตอนรับเข้า) — ต้นทุนวัตถุดิบแบบถัวเฉลี่ยเคลื่อนที่จากการรับเข้าจริง

- สถานะ: **เสนอ** · 25 ก.ย. 2569 (ร่างจากทีม POS — สเปก POS §4.10 ก้อน 5, เจ้าของตัดสิน Q49) · **แก้ ADR-0026 ข้อ 1** (ต้นทุนมาจาก "ราคาซื้อล่าสุด") **และข้อ 7** (แก้ราคาซื้อแล้วต้นทุนทุกเมนูเปลี่ยนตาม) · ขยาย ADR-0027 ข้อ 3 (รับเข้า)
- บริบท: ต้นทุนต่อแก้วตอนนี้คำนวณจากราคาซื้อล่าสุดของวัตถุดิบ (`cost_per_use_unit = buy_price ÷ pack_to_use_factor`) · ราคาซื้อจริงแต่ละครั้งไม่เท่ากัน ต้นทุนมาตรฐานทำให้กำไรไม่ตรงกับเงินที่จ่ายจริง · เจ้าของเลือก (Q32): ต้นทุนถัวเฉลี่ยจากการรับเข้าจริง · ค่าจาก Excel เป็นแค่ต้นทุนตั้งต้น · การนำเข้าเปลี่ยนแค่ "ราคาอ้างอิง" ไม่แตะค่าเฉลี่ย · บิลแช่แข็งต้นทุน ณ ตอนขาย (ADR-0009 ยังถือ) · POS มีตรรกะนี้ในแผน 4 (`packages/domain/src/stock/` + D57) ใช้เป็นต้นแบบ
- ตัดสินใจ:
  1. `ingredients` เพิ่ม `avg_cost_per_use_unit numeric(14,6) not null` · ตั้งต้นตอน migrate = `cost_per_use_unit` ปัจจุบัน · `buy_price` เดิม **เปลี่ยนความหมายเป็น "ราคาอ้างอิง"** (หน้าเว็บ/เทมเพลตเรียก "ราคาอ้างอิง") · `cost_per_use_unit` (generated) = ต้นทุนอ้างอิง ใช้แสดงเทียบเท่านั้น
  2. **รับเข้าที่มีราคาจ่ายจริง** (เว็บ/บอท — ADR-0027): ราคาต่อหน่วยใช้ `u = ราคาจ่ายต่อหน่วยซื้อ ÷ pack_to_use_factor` · คงเหลือก่อนรับ `q0` (จาก `v_stock_levels`) · จำนวนรับ `q` (หน่วยใช้) · ถ้า `q0 > 0`: `avg ใหม่ = round6((q0 × avg เดิม + q × u) ÷ (q0 + q))` · ถ้า `q0 ≤ 0`: `avg ใหม่ = round6(u)` · หลายบรรทัดวัตถุดิบเดียวกันในการรับครั้งเดียวรวมเป็นก้อนเดียวก่อน (ต้นทุนรวม ÷ จำนวนรวม — D57 ของ POS) · `round6` = ปัดครึ่งออกจากศูนย์ 6 ตำแหน่ง (`round(numeric, 6)`) · `stock_movements.unit_cost_at` ของการรับ = `u` · รับเข้าที่ไม่ใส่ราคา → avg ไม่เปลี่ยน + คำเตือน "ไม่มีราคา ต้นทุนเฉลี่ยไม่ขยับ"
  3. การรับเข้าไม่เปลี่ยนราคาอ้างอิงโดยอัตโนมัติ · ติ๊ก "อัปเดตราคาอ้างอิงด้วย" ได้ (พฤติกรรมเดิมของ ADR-0027 ข้อ 3 ย้ายมาเป็นตัวเลือกนี้)
  4. นับ (`count`) · ของเสีย (`waste`) · ปรับ (`adjust`) · ขาย · ยกเลิกบิล **ไม่เปลี่ยน avg** · movement เหล่านี้ใช้ `unit_cost_at` = avg ณ ตอนนั้น
  5. **ต้นทุนแช่แข็งของบิล** (`order_items.unit_cost`, `cost_snapshot_json`) และ `v_variant_cost`/`v_base_cost` ใช้ `avg_cost_per_use_unit` แทน `cost_per_use_unit` · บิลเก่าไม่เปลี่ยน (ADR-0009) · แก้บิล (ADR-0029): รายการเดิมคงต้นทุนเดิม รายการใหม่ใช้ avg ปัจจุบัน
  6. รับเข้าผ่าน API: `buy_price` ถูกเพิกเฉยตามเดิม (ADR-0041) → **avg ไม่เปลี่ยน**
  7. **นำเข้าเทมเพลต/แก้หน้าวัตถุดิบ** เปลี่ยนเฉพาะราคาอ้างอิง ไม่แตะ avg · modal "กระทบ N เมนู" (ADR-0026 ข้อ 7) แสดงต้นทุนอ้างอิงเทียบต้นทุนเฉลี่ยจริง ไม่ใช่ "ต้นทุนจะเปลี่ยนเป็น"
  8. **owner ปรับ avg เอง** ได้ (Q49): RPC `set_avg_cost(p_shop_id, p_staff_id, p_ingredient_id, p_new_avg, p_reason)` owner เท่านั้น เหตุผลบังคับ ลง `audit_log` (ค่าเดิม ค่าใหม่ เหตุผล ผู้แก้ เวลา) · หน้าวัตถุดิบแสดง **ประวัติต้นทุนเฉลี่ย** (รับเข้าที่เปลี่ยน avg + การปรับเอง เรียงเวลา) · ไม่แก้บิลเก่า
  9. สิทธิ์เห็น avg ตาม `can_see_cost` (ADR-0034) · API ไม่ส่ง avg (ADR-0035 ข้อ 3)
- ทางเลือกที่ไม่เลือก: ต้นทุนมาตรฐานจากราคาล่าสุด (เดิม — ไม่ตรงเงินจริง) · FIFO ตามล็อต (ต้องติดตามล็อตทุกชิ้น ซับซ้อนเกินร้าน 2 คน) · ให้การนำเข้าตั้ง avg (ไฟล์ Excel ไม่ใช่ราคาจ่ายจริง — เจ้าของสั่งห้าม)
- ผลที่ตามมา: migration ใหม่ (คอลัมน์ + ตั้งต้น + แก้ `stock_receive` `v_variant_cost` `v_base_cost` `dayo_impl_price_line` (ต้นทุน) `import_catalog` (แตะแค่ราคาอ้างอิง) + `set_avg_cost`) · หน้าวัตถุดิบ/รับเข้า · เทมเพลต Excel หัวคอลัมน์ "ราคาอ้างอิง" · DATA-CONTRACT §2.3/§4.1 · GLOSSARY ("ต้นทุนเฉลี่ย", "ราคาอ้างอิง") · เทสต์ ±0.01 ของ ADR-0026 (ต้นทุนเทียบ Excel) ใช้ได้เฉพาะก่อนมีการรับเข้าครั้งแรก — เปลี่ยนเป็นเทสต์ "หลัง migrate avg = ต้นทุนเดิมทุกตัวแปร" · เทสต์ใหม่: รับ 2 ครั้งราคาต่างกัน · คงเหลือติดลบแล้วรับ · หลายบรรทัดในใบเดียว · นำเข้าแล้ว avg ไม่เปลี่ยน · shared (`variantCost`) ใช้ avg และเท่ากับ SQL
