# ADR-P8 (เลขถัดไปตอนรับเข้า) — นำเข้าเทมเพลตแบบ "ทับทั้งหมด": ไฟล์เป็นความจริงทั้งก้อน · ซ่อนไม่ลบ · ดูความต่างก่อนยืนยัน · บันทึกการนำเข้า

- สถานะ: **เสนอ** · 25 ก.ย. 2569 (ร่างจากทีม POS — เจ้าของตัดสิน Q50) · ขยาย ADR-0025 ข้อ 3 (เทมเพลตนำเข้า/ส่งออก) · ADR-0025 ข้อ 2 (ไฟล์ `DA-YO_เมนู.xlsx` นำเข้าครั้งแรกครั้งเดียว) **คงเดิม**
- บริบท: เจ้าของต้องการแก้เมนูทีละมากด้วย Excel: ส่งออกเทมเพลตของระบบ → แก้ → นำเข้า และให้ไฟล์เป็นความจริงทั้งก้อน (Q25/Q30/Q31) · ระบบมีอยู่แล้วเกือบครบ: `import_catalog` โหมด `replace` (ทับเฉพาะกลุ่มที่มีในไฟล์ ของที่ไม่อยู่ในไฟล์ → `is_active=false`) · `preview_import` (ความต่างต่อตาราง rollback เสมอ) · ตาราง `imports` (ชนิด โหมด ชื่อไฟล์ ผู้นำเข้า จำนวน คำเตือน diff) · ต้องยืนยันด้วยการพิมพ์ "ทับทั้งหมด" (DATA-CONTRACT §7) · ที่ขาด: (ก) ชีตที่ไม่อยู่ในไฟล์ถูกข้ามเงียบ ๆ — ลบชีตผิดแล้วนำเข้าจะดูเหมือนสำเร็จแต่ไม่ได้เป็น "ทั้งก้อน" (ข) หน้าตรวจความต่างยังไม่แสดงรายชื่อสิ่งที่จะถูกซ่อน (ค) บันทึกการนำเข้าไม่มีลายนิ้วมือของไฟล์ (ง) เมื่อมีต้นทุนถัวเฉลี่ย (P5) ราคาในไฟล์ต้องไม่แตะค่าเฉลี่ย
- ตัดสินใจ:
  1. โหมดใหม่ **`replace_all`** (ชื่อบนหน้าจอ "ทับทั้งหมด") แยกจาก `replace` เดิม (ทับรายชีต) และ `merge` (ค่าเริ่มต้น)
  2. `replace_all` ต้องมี **ทุกชีตแคตตาล็อก**: `วัตถุดิบ` `เบส` `ส่วนผสมเบส` `เมนู` `ตัวแปรเมนู` `สูตร` `ตัวเลือก` `SOP` `ความรู้` `โปรโมชั่น` `ช่องทางขาย` `วิธีชำระ` · ตรวจครบ **ก่อนเขียนอะไรทั้งสิ้น** (Q50) ตามข้อ 2.1 · ชีต `สต็อกคงเหลือ` และชีตรายงานไม่อยู่ในโหมดนี้ (สต็อกเป็น movement — ADR-0027)
  2.1 **ตรวจโครงไฟล์ก่อนเขียน** สองชั้น: (ก) ในเบราว์เซอร์หลังอ่านไฟล์ด้วย SheetJS ก่อนเรียก RPC ใด ๆ (ข) ซ้ำใน `preview_import`/`import_catalog` ก่อนแตะตาราง (payload ที่ขาดชีต/คอลัมน์ = `DY422` ไม่มีการเขียน) · ตรวจ: ชีตที่ต้องมีครบ · ในแต่ละชีต คอลัมน์บังคับ (ชื่อคอลัมน์ระบบในแถว 2 ตาม DATA-CONTRACT §7) ครบ · ไม่ครบ = **ปฏิเสธทั้งไฟล์** และแสดงรายการภาษาไทยครบทุกข้อในครั้งเดียว เช่น:
      > นำเข้าไม่ได้ ไฟล์ไม่ครบ ยังไม่มีการเปลี่ยนแปลงใด ๆ
      > • ไม่มีชีต: `ส่วนผสมเบส`, `ความรู้`
      > • ชีต `ตัวแปรเมนู` ขาดคอลัมน์: ราคา (`price`), สถานะ (`is_active`)
      > • ชีต `สูตร` ขาดคอลัมน์: ปริมาณ (`qty`)
      ข้อความบอกทั้งหัวไทย (แถว 1) และชื่อระบบ (แถว 2) · รายชื่อคอลัมน์บังคับต่อชีตกำหนดที่เดียวใน `packages/shared/src/template.ts` ใช้ทั้งเบราว์เซอร์และเทสต์ของ RPC
  3. แถวในไฟล์ → สร้าง/แก้ตามคีย์ธรรมชาติ (DATA-CONTRACT §2.1 ข้อ 2) · แถวที่มีในระบบแต่ไม่อยู่ในไฟล์ → `is_active=false` **ไม่ลบเด็ดขาด** · บรรทัดลูกที่ไม่มี `is_active` (`recipe_lines`, `base_lines`) ของแถวที่อยู่ในไฟล์ถูกแทนด้วยของในไฟล์ตรงตัว (บิลไม่อ้างบรรทัดสูตร ใช้ snapshot — ADR-0026 ข้อ 6)
  4. **หน้าตรวจก่อนยืนยัน**: ต่อชีต แสดงจำนวน เพิ่ม/แก้/ซ่อน และ **รายชื่อทุกแถวที่จะถูกซ่อน** · เตือนเพิ่มเมื่อสิ่งที่จะถูกซ่อนยังถูกอ้างโดยของที่ active (เช่น โปรที่ active อ้างเมนูที่จะซ่อน · ช่องทางที่ active ใช้วิธีชำระที่จะซ่อน — ตามกติกา `DY409` เดิม) · error ระดับแถวมีแม้แถวเดียว = นำเข้าไม่ได้ (กติกาเดิม) · ยืนยันด้วยการพิมพ์ "ทับทั้งหมด"
  5. **บันทึกการนำเข้า** (`imports`): เพิ่ม `file_sha256`, `file_bytes`, `sheet_names text[]` · มีอยู่แล้ว: ผู้นำเข้า เวลา ชื่อไฟล์ โหมด จำนวน คำเตือน diff · หน้า "ประวัติการนำเข้า" แสดงทั้งหมด · ไม่เก็บตัวไฟล์บนเซิร์ฟเวอร์ (ADR-0021)
  6. หลัง P5: คอลัมน์ราคาในชีต `วัตถุดิบ` = **ราคาอ้างอิง** · การนำเข้าไม่เปลี่ยน `avg_cost_per_use_unit`
  7. นำเข้าเสร็จ → purge cache (เดิม) · ฉบับแคตตาล็อกเพิ่มเอง (trigger ของ P1) แท็บเล็ตดึงของใหม่ในรอบถัดไป
  8. owner เท่านั้น (ADR-0034 นำเข้า/ส่งออก)
- ทางเลือกที่ไม่เลือก: ชีตที่ขาด = ซ่อนทุกอย่างในกลุ่มนั้น (อันตราย) · ลบของที่ไม่อยู่ในไฟล์ (ขัดกฎเหล็กข้อ 5) · นำเข้าไฟล์ `DA-YO_เมนู.xlsx` เดิมซ้ำ (ขัด ADR-0025 ข้อ 2)
- ผลที่ตามมา: migration (`import_catalog`/`preview_import` รับ `replace_all` · คอลัมน์ใหม่ `imports`) · หน้า `/settings` นำเข้า (ตัวเลือกโหมด + รายชื่อที่จะซ่อน) · SheetJS ในเบราว์เซอร์คำนวณ sha256 ด้วย Web Crypto · DATA-CONTRACT §7 · เทสต์: ไฟล์ขาดชีต = ปฏิเสธ และข้อความบอกชื่อชีตครบ · ชีตขาดคอลัมน์บังคับ = ปฏิเสธ และบอกชีต + คอลัมน์ · ทั้งสองกรณีไม่มีแถวใดในฐานเปลี่ยน และไม่มีแถว `imports` ใหม่ · เมนูที่ไม่อยู่ในไฟล์ถูกซ่อนและยังเปิดดูบิลเก่าได้ · preview แล้ว rollback ไม่เปลี่ยนอะไร · ฉบับแคตตาล็อกเพิ่มหลังนำเข้า
