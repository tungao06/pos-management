# ADR-P6 (เลขถัดไปตอนรับเข้า) — ตอกบัตรเข้า-ออก และใบเงินเดือน

- สถานะ: **เสนอ** · 25 ก.ย. 2569 (ร่างจากทีม POS — สเปก POS §4.10 ก้อน 6, เจ้าของตัดสิน Q44, Q47) · เรื่องใหม่ ไม่แก้ ADR เดิม
- บริบท: ร้านจะจ้างพนักงานแบบผสม (Q28/Q33): รายเดือน = เงินเดือนคงที่ จ่ายเดือนละครั้ง · รายวัน/รายชั่วโมง = ตอกบัตรเข้า-ออกที่แท็บเล็ตด้วย PIN ของตัวเอง คิดชั่วโมง × อัตรา จ่ายรายสัปดาห์ · ใบเงินเดือนต่องวดให้ owner ตรวจก่อนจ่าย · การจ่ายบันทึกเป็นค่าใช้จ่าย (P4) — จากลิ้นชักลดเงินสดที่ควรมีของกะ หรือจากธนาคาร · ประกันสังคม/หัก/เพิ่ม กรอกเองเป็นบรรทัด ไม่คำนวณตามกฎหมาย · พนักงานทุกคนอยู่ในตาราง `staff` ซึ่งต้องมี `line_user_id` (Q47: ทุกคนต้องเพิ่มบอทและ owner อนุมัติก่อน)
- ตัดสินใจ:
  1. ผู้เขียน = **แท็บเล็ต** ทั้งหมด (ตอกบัตร อัตรา ใบเงินเดือน) · เว็บอ่านอย่างเดียว (owner) · ส่งผ่าน `POST /v1/pos/push` scope ใหม่ `payroll:write` · ตารางทั้งหมด append-only (`id` จากแท็บเล็ต · `api_client_id` · RLS เปิดไม่มี policy · ในไฟล์สำรอง)
  2. `staff_pay_profiles`: `staff_id`, `pay_type` (`monthly`/`daily`/`hourly`), `rate numeric(10,2)` (บาท/เดือน, /วัน, /ชั่วโมง), `pay_cycle` (`monthly`/`weekly`), `effective_from date`, `created_by` (owner) · เปลี่ยนอัตรา = แถวใหม่
  3. `time_punches`: `staff_id`, `kind` (`in`/`out`), `at timestamptz`, `created_by` (= `staff_id` ยืนยันด้วย PIN ตัวเอง) · `time_punch_fixes`: `punch_id` (หรือ null = เพิ่มการตอกที่ลืม พร้อม `staff_id`, `kind`), `new_at`, `reason`, `approved_by` (owner)
  4. `pay_sheets`: `staff_id`, `period_from`, `period_to`, `status` (`approved`/`void`), `gross`, `net`, `approved_by`, `approved_at` · `pay_sheet_lines`: `pay_sheet_id`, `kind` (`salary`/`days`/`hours`/`addition`/`deduction`/`social_security`), `description`, `qty numeric(10,3)`, `rate`, `amount` (บวกหรือลบตาม kind) · ใบที่มีการตอกไม่ครบคู่ในงวดอนุมัติไม่ได้ · `approved` แล้วแก้ไม่ได้ ยกเลิกได้ด้วย `void` แล้วออกใบใหม่
  5. คิดเงินที่แท็บเล็ตใน `@dayo/domain` เป็นสตางค์ · RPC ฝั่งนี้คิดซ้ำจากตอกบัตร+อัตราในฐาน ต่างกัน → `pay_sheets.calc_mismatch = true` บันทึกตามที่ owner อนุมัติ (แบบเดียวกับ `amount_mismatch`)
  6. การจ่าย = แถว `expenses` หมวด "เงินเดือน" อ้าง `pay_sheet_id` (P4) · จ่ายจากลิ้นชักต้องมีกะเปิดอยู่ (P3)
  7. `GET /v1/pos/payroll-data?from=` (scope `payroll:write`) คืนอัตรา ตอกบัตร และใบเงินเดือนตั้งแต่วันที่ให้ — ใช้ตอนเปลี่ยนเครื่อง
  8. ต้องล็อกในสเปก POS ก่อนเริ่มก้อน 6: หน่วยนับเวลา (เสนอ: นาทีเต็ม ตัดวินาที) · วันทำงานของรายวัน (เสนอ: วันที่มีคู่เข้า-ออกครบ) · การปัดค่าจ้างรายชั่วโมง (ครึ่งออกจากศูนย์ที่ 1 สตางค์) · ตัวอย่างตัวเลขที่เทสต์ต้องได้ · รูปฟิลด์ชนิด push `pay_profile` `time_punch` `time_punch_fix` `pay_sheet`
- ทางเลือกที่ไม่เลือก: ตอกบัตรผ่านบอท LINE (พนักงานตอกจากที่ไหนก็ได้ ไม่ต้องอยู่หน้าร้าน) · คำนวณประกันสังคม/ภาษีอัตโนมัติ (เจ้าของไม่ต้องการ กฎเปลี่ยนบ่อย) · ทำใบเงินเดือนบนเว็บ (เงินเดือนเป็นงานของเครื่องมือเงิน POS ตาม C1 และการจ่ายจากลิ้นชักผูกกับกะบนแท็บเล็ต)
- ผลที่ตามมา: migration ใหม่ (5 ตาราง + ชนิดใหม่ใน `api_pos_push` + RPC คิดซ้ำ + `api_payroll_data`) · scope `payroll:write` · หน้าเว็บอ่านใบเงินเดือน (owner) · Export Excel ชีต `ตอกบัตร` / `เงินเดือน` · `backup_dump_table` · ข้อมูลค่าจ้างเห็นได้เฉพาะ owner (ADR-0034 — เพิ่มแถว "เงินเดือน/ตอกบัตรของคนอื่น: owner เท่านั้น") · GLOSSARY ("ตอกบัตร", "ใบเงินเดือน", "งวด")
