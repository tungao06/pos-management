# ADR-P4 (เลขถัดไปตอนรับเข้า) — ค่าใช้จ่ายร้าน และกำไรสุทธิ (รวมรายงานกำไรบนแท็บเล็ตเฉพาะ owner)

- สถานะ: **เสนอ** · 25 ก.ย. 2569 (ร่างจากทีม POS — สเปก POS §4.10 ก้อน 4 และ §7 ข้อ 10 · เจ้าของตัดสิน Q45, Q46 (D69, D70) · แก้ตามรีวิวรอบ 1 ข้อ 11, 15, 19 · ข้อ 6 ตามคำตัดสิน Q54 ทาง ก (D79)) · ขยาย ADR-0032 (แดชบอร์ด: เพิ่มกำไรสุทธิ) · **แก้ ADR-0035 ข้อ 3 และ ADR-0040 ข้อ 3** ("คำตอบจาก API ไม่มีต้นทุน/กำไรเสมอ") ด้วยข้อยกเว้นเดียว: `POST /v1/pos/profit` สำหรับ owner
- บริบท: แดชบอร์ดมีแค่กำไรขั้นต้น (ยอดขาย − ต้นทุน − ค่าธรรมเนียม) · เจ้าของต้องการบันทึกค่าใช้จ่ายรายการ (หมวด จำนวน วันที่ จ่ายจากลิ้นชักหรือธนาคาร) และดูกำไรสุทธิ (Q29) · ค่าใช้จ่ายที่จ่ายจากลิ้นชักต้องลดเงินสดที่ควรมีของกะ (P3) · เงินเดือนที่จ่ายแล้วก็เป็นค่าใช้จ่าย (P6) · การซื้อวัตถุดิบเข้าสต็อกนับเป็นต้นทุนขายผ่านต้นทุนแช่แข็งของบิลอยู่แล้ว ถ้านับเป็นค่าใช้จ่ายอีกจะหักซ้ำ · เจ้าของต้องการเห็นกำไรสุทธิบนแท็บเล็ตด้วย แต่ **เฉพาะตอนที่ผู้ล็อกอินเป็น owner** (Q45) · ADR-0035 ข้อ 3 / ADR-0040 ข้อ 3 ห้าม API ส่งต้นทุน/กำไร เพราะ key อยู่บนเครื่อง POS ที่เสี่ยงหลุดกว่าเซิร์ฟเวอร์ และ `staff_ref` ไม่ใช่ที่มาของสิทธิ์
- ตัดสินใจ:
  1. `expense_categories` (แก้บนเว็บ owner · ห้ามลบใช้ `is_active` · `audit_log`): `name`, `counts_in_profit bool`, `sort_order`, `is_active` · seed: ค่าเช่า · ค่าน้ำค่าไฟ · ค่าแก๊ส · อุปกรณ์/ซ่อม · การตลาด · เงินเดือน (`counts_in_profit=true`) · **ซื้อวัตถุดิบเข้าสต็อก** (`counts_in_profit=false`) · อื่น ๆ · หมวดอยู่ในฉบับแคตตาล็อก (P1) และส่งให้แท็บเล็ตใน `GET /v1/pos/catalog` เป็น `expense_categories: [{id, name, counts_in_profit, active}]` **ระดับเดียวกับ `staff`** (ไม่อยู่ใน `catalog` ซึ่งต้องเป็นรูป `OrderCatalog` ตรงตัว)
  2. `expenses` (append-only · `id` จากแท็บเล็ต): `spent_on date`, `category_id`, `description` (≤ 200), `amount > 0`, `paid_from` (`drawer`/`bank`), `shift_id` (บังคับเมื่อ `drawer` — check), `pay_sheet_id` (P6), `created_by`, `voided_at`/`voided_by`/`void_reason` (ตั้งครั้งเดียว)
  3. ชนิดใหม่ของ `POST /v1/pos/push` (scope ใหม่ `expense:write`): `expense` · `expense_void` (ค่าใช้จ่ายจากลิ้นชักยกเลิกได้เมื่อ `voided_at` ≤ `counted_at` ของการนับเงินของกะนั้น หรือกะยังไม่ถูกนับ — ตัดสินด้วยเวลาในแถว ไม่ใช่สถานะ ณ ตอนแถวมาถึง · จากธนาคารยกเลิกได้เสมอ) · ค่าใช้จ่ายจากลิ้นชักและ `expense_void` อยู่ในช่องเดียวกับแถวของกะนั้นในคิวแท็บเล็ต (P3 ข้อ 5) · อ้างกะที่ยังไม่มา = บันทึกได้ (ผูกทีหลัง)
  4. ผู้เขียนค่าใช้จ่าย = **แท็บเล็ตเท่านั้นในตอนนี้** (Q46) · เว็บอ่านอย่างเดียว (รายการ + ตัวกรองหมวด/ช่วงวัน + Export)
  5. **กำไรสุทธิ** RPC `dashboard_net_profit(p_shop_id, p_from, p_to, p_staff_id)` owner เท่านั้น = Σ `total_amount` (บิล ok ทุกแหล่ง ตาม `sale_date`) + Σ `pos_excluded_orders.total` (บิลนอกระบบกลาง ตามวันที่ไทยของ `sold_at` · ป้ายกำกับ · P3) − Σ `channel_fee_amount` − Σ `cost_total` − Σ `amount` ของค่าใช้จ่ายที่ไม่ถูกยกเลิกและหมวด `counts_in_profit` (ตาม `spent_on`) · แสดงบนแดชบอร์ดเว็บเป็นรายเดือน + แยกหมวด
  6. **รายงานกำไรบนแท็บเล็ต — ข้อยกเว้นเดียวของ ADR-0035 ข้อ 3 / ADR-0040 ข้อ 3** (เจ้าของตัดสิน Q54 ทาง ก · D79): owner พิสูจน์ตัวด้วย **การล็อกอิน LINE บนเว็บนี้** ไม่ใช่ `staff_id` ที่แท็บเล็ตอ้าง
     - scope ใหม่ `reports:profit` — **ไม่อยู่ในชุดเริ่มต้น** owner ต้องเปิดให้ key ของเครื่องขายเองที่ `/settings/api-clients`
     - **ออกรหัส (เว็บ · owner)**: หน้า `/settings/api-clients` ปุ่ม "เปิดดูกำไรบนแท็บเล็ต" ที่แถวของ key ที่มี `reports:profit` (มี key เดียวก็เลือกให้เอง) · `requireRole('owner')` + RPC `issue_profit_unlock_code(p_shop_id, p_staff_id, p_api_client_id, p_code_hash)` ตรวจ owner active อีกชั้น (ADR-0034) · รหัสตัวเลข 6 หลัก สุ่มด้วย Web Crypto ฝั่งเซิร์ฟเวอร์ แสดงครั้งเดียว · เก็บเฉพาะ `sha256(shop_id ‖ api_client_id ‖ รหัส)` · อายุ 5 นาที · ใช้ได้ครั้งเดียว · ผูกร้าน + key · ออกใหม่ = รหัสเดิมที่ยังไม่ใช้ของ key นั้นถูกยกเลิก
     - **แลกรหัส (แท็บเล็ต)**: `POST /v1/pos/profit-session` (scope `reports:profit`) body `{code, staff_id}` (`staff_id` บันทึกเท่านั้น) → RPC `api_open_profit_session` คืน `{session_token, expires_at}` · token สุ่ม 32 ไบต์ (`dps_` + base64url) เก็บเป็น sha256 · หมดอายุก่อนเที่ยงคืนไทยถัดไป (`now() < (วันที่ไทยตอนออก + 1 วัน) at time zone 'Asia/Bangkok'`) แต่ไม่เกิน 16 ชั่วโมง · รหัสผิดนับ `failed_attempts` ของรหัสที่ยังใช้ได้ของ key นั้น ครบ 5 = รหัสเป็นโมฆะ · ปฏิเสธด้วย JSON ไม่ raise ข้อความเดียวกันทุกกรณี · `audit_log` `profit_code_ok`/`profit_code_fail`/`profit_code_voided`
     - ตาราง `profit_unlock_codes (id, shop_id, api_client_id, code_hash, created_by, created_at, expires_at, used_at, failed_attempts, voided_at, void_reason)` · `profit_sessions (id, shop_id, api_client_id, token_hash, unlock_code_id, owner_staff_id, created_at, expires_at, revoked_at, revoked_by, last_used_at)` · RLS เปิดไม่มี policy · ไม่อยู่ในไฟล์สำรอง · `heartbeat` ลบแถวหมดอายุเกิน 7 วัน
     - **รายละเอียดความปลอดภัย**: นับ `failed_attempts` ใต้ `select … for update` · รหัสเป็นโมฆะเพราะผิดครบ 5 ครั้ง → แจ้ง 🟡 Discord ช่องระบบ (ADR-0044) · route `profit-session`/`profit` ห้าม log body · RPC รับรหัส/token เป็น `text` และตรวจรูปก่อน cast (`^[0-9]{6}$` · `^dps_[A-Za-z0-9_-]{43}$`) — ไม่มี `22P02` ที่สะท้อนค่า · แท็บเล็ตใช้ `expires_at` แค่แสดงผล
     - **audit**: `audit_log.action` เพิ่ม `profit_code_issued` `profit_code_ok` `profit_code_fail` `profit_code_voided` `profit_session_created` `profit_session_revoke` `profit_view`
     - **เพิกถอน (เว็บ)**: หน้าเดียวกันแสดงสิทธิ์ที่ยังใช้ได้ + ปุ่ม "ยกเลิก" / "ยกเลิกทั้งหมด" · ยกเลิกเองเมื่อ key ถูกเพิกถอน/เอา scope ออก หรือ owner ที่เปิดไม่เป็น owner active แล้ว (ตรวจทุกครั้งที่ใช้)
     - **`POST /v1/pos/profit`** body `{session_token, from, to}` (`YYYY-MM-DD` · ช่วง ≤ 366 วัน · token ใน body ไม่ต้องขยาย CORS ไม่อยู่ใน URL) · RPC `api_pos_net_profit(p_shop_id, p_api_client_id, p_session_token, p_from, p_to)` ต้องมี scope `reports:profit` **และ** token ที่ยังใช้ได้ของ key เดียวกัน · ไม่ผ่าน = JSON `{ok:false, error:{code:'DY403'}}` (ไม่ raise — แถว audit ถูก commit) แล้ว route แปลงเป็น HTTP 403 ข้อความเดียวกันทุกกรณี
     - คำตอบ **ยอดรวมเท่านั้น** `{from, to, bills, revenue, channel_fees, cost_of_goods, gross_profit, expenses_total, expenses_by_category:[{category, amount}], excluded_bills_total, net_profit, generated_at}` · ไม่มีต้นทุนรายเมนู/รายวัตถุดิบ/สูตร/ราคาซื้อ · ใช้สูตรเดียวกับข้อ 5
     - หัว `Cache-Control: no-store` · ทุกการเรียก (สำเร็จหรือถูกปฏิเสธ) เขียน `audit_log` action ใหม่ `profit_view` (`profit_session_id`, `owner_staff_id`, `api_client_id`, ช่วงวัน, ผล) — ขยาย check ของ `audit_log.action` (รายการเต็มในข้อ audit ข้างบน) · แดชบอร์ดเว็บแสดง "ดูกำไรจากแท็บเล็ตล่าสุด: <เวลา> โดย <ชื่อ>"
     - ข้อกำหนดฝั่งแท็บเล็ต (สเปก POS §4.10 ก้อน 4): เมนูกำไรแสดงเฉพาะ owner · ใส่ PIN owner ซ้ำ แล้วใส่รหัสจากเว็บ · token อยู่ในหน่วยความจำของแอปที่รันอยู่ (อยู่รอดการสลับหน้า — ใส่รหัสวันละครั้ง) ล้างเมื่อออกจากระบบ สลับผู้ใช้ ล็อกจอ โหลดแอปใหม่ หรือหมดอายุ · ตัวเลขกำไรอยู่ในหน่วยความจำของหน้ากำไรเท่านั้น ล้างเมื่อออกจากหน้า · ทั้งสองอย่างไม่เก็บลงเครื่อง
     - **ความเสี่ยงที่เหลือ**: แท็บเล็ตที่ยังปลดล็อกระหว่างวันขณะสิทธิ์ของ owner ยังใช้ได้ — ใครหยิบเครื่องก่อนล็อกจอเปิดหน้ากำไรได้โดยไม่ต้องใช้รหัส · รับมือ: ล็อกจออัตโนมัติ 10 นาทีล้าง token + หมดอายุสิ้นวันทำการ + เพิกถอนจากเว็บทันที + `audit_log` ทุกขั้น · key ที่มี scope นี้รั่วอย่างเดียวดูกำไรไม่ได้ (ต้องมีรหัสจากเว็บ) · **endpoint เปิดใช้ได้ในก้อน 4**
  7. endpoint อื่นทั้งหมดของ `/api/v1` ยังไม่มีต้นทุน/กำไรตาม ADR-0035 ข้อ 3 / ADR-0040 ข้อ 3 เดิม
- ทางเลือกที่ไม่เลือก: ค่าใช้จ่ายไม่มีหมวด (ทำรายงานไม่ได้) · นับการซื้อวัตถุดิบเป็นค่าใช้จ่าย (หักต้นทุนซ้ำ) · ให้เว็บบันทึกค่าใช้จ่ายด้วย (สองผู้เขียนต่อตาราง — ทบทวนภายหลัง) · ส่งกำไรใน `GET /v1/pos/catalog` หรือคำตอบ push (ไปถึงทุกคนที่ล็อกอินและถูกเก็บลงเครื่อง) · เชื่อบทบาทหรือ `staff_id` ที่แท็บเล็ตส่งมา (id ของ owner อยู่ในรายชื่อที่ทุกเครื่องได้ — ไม่ใช่หลักฐาน) · token อายุยาว/เก็บลงเครื่อง (เครื่องหายแล้วรั่วนาน) · ไม่แสดงกำไรบนแท็บเล็ตเลย (เจ้าของต้องการ)
- ผลที่ตามมา: migration ใหม่ (2 ตาราง + seed + ชนิดใหม่ใน `api_pos_push` + `dashboard_net_profit` + `api_pos_net_profit` + `profit_unlock_codes` `profit_sessions` + `issue_profit_unlock_code` `api_open_profit_session` + `audit_log.action` เพิ่ม `profit_view` `profit_code_issued` `profit_code_ok` `profit_code_fail` `profit_code_voided` `profit_session_created` `profit_session_revoke` + ฉบับแคตตาล็อกนับ `expense_categories`) · scope `expense:write` และ `reports:profit` · `app/api/v1/pos/profit/route.ts` · `app/api/v1/pos/profit-session/route.ts` · ปุ่มออกรหัส + รายการสิทธิ์/เพิกถอนใน `/settings/api-clients` · หน้าเว็บหมวดค่าใช้จ่าย + รายงาน + บรรทัด "ดูกำไรล่าสุด" · Export Excel ชีต `ค่าใช้จ่าย` (ADR-0021) · `backup_dump_table` · DATA-CONTRACT · API.md (ข้อยกเว้นต้นทุน/กำไร) · GLOSSARY ("ค่าใช้จ่าย", "กำไรสุทธิ") · เทสต์: ค่าใช้จ่าย ฿120 จากลิ้นชักลด expected ของกะ (P3) 120.00 · หมวดซื้อวัตถุดิบไม่ลดกำไรสุทธิ · ยกเลิกแล้วไม่นับ · `/v1/pos/profit` ไม่มี token/หมดอายุ/ถูกยกเลิก/ของ key อื่น/owner ถูกลดบทบาท = `DY403` ข้อความเดียวกัน **และมีแถว `profit_view` ของการถูกปฏิเสธค้างอยู่ในฐาน** · ส่ง `staff_id` owner อย่างเดียวไม่มี token = 403 · รหัส: หมดอายุ 5 นาที ใช้ซ้ำไม่ได้ ใช้กับ key อื่นไม่ได้ ผิด 5 ครั้งเป็นโมฆะ · token หมดอายุสิ้นวันทำการ ≤ 16 ชม. · เพิกถอนแล้ว 403 · แท็บเล็ต: สลับหน้าแล้ว token ยังอยู่ (ตัวเลขถูกล้าง) · ล็อกจอ/ออกจากระบบ/โหลดใหม่ แล้ว token หาย · ไม่มีรหัส/token ข้อความเปล่าในฐาน · มี audit `profit_code_issued` / `profit_session_created` / `profit_session_revoke` (เองและอัตโนมัติ) / `profit_code_voided` + Discord · คำขอผิดพร้อมกัน 10 ครั้งนับไม่เกิน 5 · รหัส/token ผิดรูปไม่มี `22P02` และไม่มี `dps_` ใน log · token ใช้ไม่ได้ตั้งแต่ 00:00 ไทย · key ไม่มี `reports:profit` = 403 · ทุกการเรียกมี `profit_view` · ผลเท่ากับ `dashboard_net_profit` · **security review บังคับ** · **ต้องล็อกรูปฟิลด์ชนิด push ในสเปก POS ก่อนเริ่มก้อน 4**
