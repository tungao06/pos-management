# ADR-P4 (เลขถัดไปตอนรับเข้า) — ค่าใช้จ่ายร้าน และกำไรสุทธิ (รวมรายงานกำไรบนแท็บเล็ตเฉพาะ owner)

- สถานะ: **เสนอ** · 25 ก.ย. 2569 (ร่างจากทีม POS — สเปก POS §4.10 ก้อน 4 และ §7 ข้อ 10 · เจ้าของตัดสิน Q45, Q46 (D69, D70) · แก้ตามรีวิวรอบ 1 ข้อ 11, 15, 19 · **ข้อ 6 รอคำตอบเจ้าของ Q54**) · ขยาย ADR-0032 (แดชบอร์ด: เพิ่มกำไรสุทธิ) · **แก้ ADR-0035 ข้อ 3 และ ADR-0040 ข้อ 3** ("คำตอบจาก API ไม่มีต้นทุน/กำไรเสมอ") ด้วยข้อยกเว้นเดียว: `POST /v1/pos/profit` สำหรับ owner
- บริบท: แดชบอร์ดมีแค่กำไรขั้นต้น (ยอดขาย − ต้นทุน − ค่าธรรมเนียม) · เจ้าของต้องการบันทึกค่าใช้จ่ายรายการ (หมวด จำนวน วันที่ จ่ายจากลิ้นชักหรือธนาคาร) และดูกำไรสุทธิ (Q29) · ค่าใช้จ่ายที่จ่ายจากลิ้นชักต้องลดเงินสดที่ควรมีของกะ (P3) · เงินเดือนที่จ่ายแล้วก็เป็นค่าใช้จ่าย (P6) · การซื้อวัตถุดิบเข้าสต็อกนับเป็นต้นทุนขายผ่านต้นทุนแช่แข็งของบิลอยู่แล้ว ถ้านับเป็นค่าใช้จ่ายอีกจะหักซ้ำ · เจ้าของต้องการเห็นกำไรสุทธิบนแท็บเล็ตด้วย แต่ **เฉพาะตอนที่ผู้ล็อกอินเป็น owner** (Q45) · ADR-0035 ข้อ 3 / ADR-0040 ข้อ 3 ห้าม API ส่งต้นทุน/กำไร เพราะ key อยู่บนเครื่อง POS ที่เสี่ยงหลุดกว่าเซิร์ฟเวอร์ และ `staff_ref` ไม่ใช่ที่มาของสิทธิ์
- ตัดสินใจ:
  1. `expense_categories` (แก้บนเว็บ owner · ห้ามลบใช้ `is_active` · `audit_log`): `name`, `counts_in_profit bool`, `sort_order`, `is_active` · seed: ค่าเช่า · ค่าน้ำค่าไฟ · ค่าแก๊ส · อุปกรณ์/ซ่อม · การตลาด · เงินเดือน (`counts_in_profit=true`) · **ซื้อวัตถุดิบเข้าสต็อก** (`counts_in_profit=false`) · อื่น ๆ · หมวดอยู่ในฉบับแคตตาล็อก (P1) และส่งให้แท็บเล็ตใน `GET /v1/pos/catalog` เป็น `expense_categories: [{id, name, counts_in_profit, active}]` **ระดับเดียวกับ `staff`** (ไม่อยู่ใน `catalog` ซึ่งต้องเป็นรูป `OrderCatalog` ตรงตัว)
  2. `expenses` (append-only · `id` จากแท็บเล็ต): `spent_on date`, `category_id`, `description` (≤ 200), `amount > 0`, `paid_from` (`drawer`/`bank`), `shift_id` (บังคับเมื่อ `drawer` — check), `pay_sheet_id` (P6), `created_by`, `voided_at`/`voided_by`/`void_reason` (ตั้งครั้งเดียว)
  3. ชนิดใหม่ของ `POST /v1/pos/push` (scope ใหม่ `expense:write`): `expense` · `expense_void` (ค่าใช้จ่ายจากลิ้นชักยกเลิกได้เมื่อ `voided_at` ≤ `counted_at` ของการนับเงินของกะนั้น หรือกะยังไม่ถูกนับ — ตัดสินด้วยเวลาในแถว ไม่ใช่สถานะ ณ ตอนแถวมาถึง · จากธนาคารยกเลิกได้เสมอ) · ค่าใช้จ่ายจากลิ้นชักและ `expense_void` อยู่ในช่องเดียวกับแถวของกะนั้นในคิวแท็บเล็ต (P3 ข้อ 5) · อ้างกะที่ยังไม่มา = บันทึกได้ (ผูกทีหลัง)
  4. ผู้เขียนค่าใช้จ่าย = **แท็บเล็ตเท่านั้นในตอนนี้** (Q46) · เว็บอ่านอย่างเดียว (รายการ + ตัวกรองหมวด/ช่วงวัน + Export)
  5. **กำไรสุทธิ** RPC `dashboard_net_profit(p_shop_id, p_from, p_to, p_staff_id)` owner เท่านั้น = Σ `total_amount` (บิล ok ทุกแหล่ง ตาม `sale_date`) + Σ `pos_excluded_orders.total` (บิลนอกระบบกลาง ตามวันที่ไทยของ `sold_at` · ป้ายกำกับ · P3) − Σ `channel_fee_amount` − Σ `cost_total` − Σ `amount` ของค่าใช้จ่ายที่ไม่ถูกยกเลิกและหมวด `counts_in_profit` (ตาม `spent_on`) · แสดงบนแดชบอร์ดเว็บเป็นรายเดือน + แยกหมวด
  6. **รายงานกำไรบนแท็บเล็ต — ข้อยกเว้นเดียวของ ADR-0035 ข้อ 3 / ADR-0040 ข้อ 3**: `POST /v1/pos/profit`
     - ⚠ **รอคำตอบเจ้าของ Q54**: การตรวจด้านล่างตรวจ "ข้ออ้าง" `staff_id` ไม่ใช่การพิสูจน์ตัวตน ซึ่งไม่ตรงกับถ้อยคำ D69 ("เซิร์ฟเวอร์เป็นคนตรวจ role จริง") · เจ้าของต้องเลือก: ยอมรับข้อจำกัดนี้เป็น D ใหม่ หรือเปลี่ยนเป็นการพิสูจน์ตัวตนจริง (เช่น token อายุสั้นที่ owner ออกจากเว็บด้วยการล็อกอิน LINE แล้วสแกนเข้าแท็บเล็ต) · **ข้อ 6 ยังไม่ออกแบบใหม่ และห้ามเปิดใช้ endpoint นี้จนกว่า Q54 ปิด** · ข้อ 1–5 และ 7 ทำได้ตามปกติ
     - scope ใหม่ `reports:profit` — **ไม่อยู่ในชุดเริ่มต้น** owner ต้องเปิดให้ key ของเครื่องขายเองที่ `/settings/api-clients`
     - body `{staff_id, from, to}` (`YYYY-MM-DD` · ช่วง ≤ 366 วัน) · POST เพื่อไม่ให้ `staff_id`/ช่วงวันอยู่ใน URL และ log
     - RPC `api_pos_net_profit(p_shop_id, p_api_client_id, p_staff_id, p_from, p_to)` **ตรวจที่เซิร์ฟเวอร์ทุกครั้ง** ไม่เชื่อบทบาทที่แท็บเล็ตอ้าง: `staff_id` ต้องเป็นพนักงานของร้าน `status='active'` และ `role='owner'` ณ ตอนเรียก ไม่งั้นปฏิเสธด้วยข้อความเดียวกันทุกกรณี (ไม่บอกว่า id มีอยู่แต่ไม่ใช่ owner) · **RPC ไม่ raise** แต่คืน JSON `{ok:false, error:{code:'DY403', message:'owner_only'}}` (แบบ `api_authenticate`) เพื่อให้แถว `audit_log` ของการถูกปฏิเสธ commit ได้ แล้ว route แปลงเป็น HTTP 403
     - คำตอบ **ยอดรวมเท่านั้น** `{from, to, bills, revenue, channel_fees, cost_of_goods, gross_profit, expenses_total, expenses_by_category:[{category, amount}], net_profit, generated_at}` · ไม่มีต้นทุนรายเมนู/รายวัตถุดิบ/สูตร/ราคาซื้อ · ใช้สูตรเดียวกับข้อ 5
     - หัว `Cache-Control: no-store` · ทุกการเรียก (สำเร็จหรือถูกปฏิเสธ) เขียน `audit_log` action ใหม่ `profit_view` (`staff_id`, `api_client_id`, ช่วงวัน, ผล) — ขยาย check ของ `audit_log.action` · แดชบอร์ดเว็บแสดง "ดูกำไรจากแท็บเล็ตล่าสุด: <เวลา> โดย <ชื่อ>"
     - ข้อกำหนดฝั่งแท็บเล็ต (อยู่ในสเปก POS §4.10 ก้อน 4 ข้อ 4): เมนูกำไรแสดงเฉพาะ owner · ใส่ PIN owner ซ้ำก่อนเปิด · ผลอยู่ในหน่วยความจำของหน้าจอเท่านั้น ไม่เก็บลงเครื่อง ไม่ cache ใน service worker · ล้างเมื่อออกจากระบบ สลับผู้ใช้ ล็อกจอ หรือออกจากหน้า
     - **ข้อจำกัดที่ยอมรับ**: การตรวจบทบาทตรวจ "ข้ออ้าง" `staff_id` ไม่ใช่การพิสูจน์ตัวตน (id ของ owner อยู่ในรายชื่อที่ `GET /v1/pos/catalog` ส่งให้) · ด่านจริงคือ scope ที่ปิดเป็นค่าเริ่มต้น + PIN บนแท็บเล็ต + เพิกถอน key ได้ทันที · key ที่มี scope นี้รั่ว = ยอดรวมรายได้/ต้นทุนขาย/ค่าใช้จ่าย/กำไรรั่ว (ไม่มีต้นทุนรายเมนู) · เห็นได้จาก `audit_log` `profit_view` และบรรทัด "ดูกำไรล่าสุด"
  7. endpoint อื่นทั้งหมดของ `/api/v1` ยังไม่มีต้นทุน/กำไรตาม ADR-0035 ข้อ 3 / ADR-0040 ข้อ 3 เดิม
- ทางเลือกที่ไม่เลือก: ค่าใช้จ่ายไม่มีหมวด (ทำรายงานไม่ได้) · นับการซื้อวัตถุดิบเป็นค่าใช้จ่าย (หักต้นทุนซ้ำ) · ให้เว็บบันทึกค่าใช้จ่ายด้วย (สองผู้เขียนต่อตาราง — ทบทวนภายหลัง) · ส่งกำไรใน `GET /v1/pos/catalog` หรือคำตอบ push (ไปถึงทุกคนที่ล็อกอินและถูกเก็บลงเครื่อง) · เชื่อบทบาทที่แท็บเล็ตส่งมา (สำเนารายชื่อในเครื่องอาจเก่า) · ไม่แสดงกำไรบนแท็บเล็ตเลย (เจ้าของต้องการ)
- ผลที่ตามมา: migration ใหม่ (2 ตาราง + seed + ชนิดใหม่ใน `api_pos_push` + `dashboard_net_profit` + `api_pos_net_profit` + `audit_log.action` เพิ่ม `profit_view` + ฉบับแคตตาล็อกนับ `expense_categories`) · scope `expense:write` และ `reports:profit` · `app/api/v1/pos/profit/route.ts` · หน้าเว็บหมวดค่าใช้จ่าย + รายงาน + บรรทัด "ดูกำไรล่าสุด" · Export Excel ชีต `ค่าใช้จ่าย` (ADR-0021) · `backup_dump_table` · DATA-CONTRACT · API.md (ข้อยกเว้นต้นทุน/กำไร) · GLOSSARY ("ค่าใช้จ่าย", "กำไรสุทธิ") · เทสต์: ค่าใช้จ่าย ฿120 จากลิ้นชักลด expected ของกะ (P3) 120.00 · หมวดซื้อวัตถุดิบไม่ลดกำไรสุทธิ · ยกเลิกแล้วไม่นับ · `/v1/pos/profit` ด้วย manager/staff/owner ที่ถูกปลด/id ไม่มีในร้าน = `DY403` ข้อความเดียวกัน **และมีแถว `profit_view` ของการถูกปฏิเสธค้างอยู่ในฐาน** · key ไม่มี `reports:profit` = 403 · ทุกการเรียกมี `profit_view` · ผลเท่ากับ `dashboard_net_profit` · **security review บังคับ** · **ต้องล็อกรูปฟิลด์ชนิด push ในสเปก POS ก่อนเริ่มก้อน 4**
