# dayo → ทีม POS: อัปเดตต่อจากโน้ต 06 (ดูกำไรทำเสร็จแล้ว)

วันที่ 26 ก.ย. 2569 · dayo `import-replace-all` (HEAD `4930a4c`) · **`/api/v1` ยังปิดอยู่** (เจ้าของสั่งเปิดเท่านั้น)

## 1. อะไรเปลี่ยนตั้งแต่โน้ต 06

- **§8 ของโน้ต 06 ("ฝั่ง dayo ยังไม่ได้ทำ") ล้าสมัยแล้ว** — ADR-0055 ทำเสร็จ: มี `POST /v1/pos/profit-view` ใช้งานได้จริง (migration 0053)
- endpoint เดิมของ P4 (`/v1/pos/profit-session`, `/profit`) ยังยกเลิก ไม่มีวันกลับมา
- **ไฟล์ตัวคิดราคา: ไม่เปลี่ยน** ตั้งแต่ `135679c` (ตรวจ git log แล้ว ไม่มี commit แตะ 7 ไฟล์) → ไม่ต้อง vendor:update ใหม่ · `pos-parity.json` เดิมยังใช้ได้ ค่า sha256 ตรงกับไฟล์ปัจจุบันทุกตัว:
  - money `2c588356…d105f3` · promotions `00752616…ff38e` · cost `3c3b3db5…ddea` · fmt `8cc04f4a…afa3`
  - shopSettings `7f936e72…5289` · types `64b3ce0d…9b30` · time `e924caa0…37c7`
- scope ใหม่ **`reports:profit`** (ไม่อยู่ในชุดเริ่มต้นของ key ใด — owner ต้องติ๊กเองที่ ตั้งค่า → API clients) ชุด scope ตอนนี้ 7 ตัว: `catalog:read, staff:read, orders:read, orders:write, stock:read, stock:write, reports:profit`
- หน้าเว็บ dayo เข้มงวดเรื่อง cookie/CSP (ADR-0060): **หน้าดูกำไรฝังใน iframe/WebView แบบฝังไม่ได้** (`frame-ancestors 'none'`, `X-Frame-Options: DENY`)
- (ข้อมูลเฉย ๆ) dayo มีบอท LINE สำหรับลูกค้า (ADR-0062/0063) ไม่กระทบ API ของ POS · เรื่อง D66 "สั่งล่วงหน้า" ของ POS เป็นเฟส ข ต้องคุยกับทีม POS ก่อน ยังไม่มีสัญญา API

## 2. ปุ่ม "ดูกำไร" บนแท็บเล็ต — POS ต้องทำอะไร (ทีละขั้น)

หลักการ: API **ไม่ส่งตัวเลขเงิน/ต้นทุน/กำไรเลย** (ADR-0040 ข้อ 3) ส่งแค่ลิงก์หน้าเว็บ ตัวเลขอยู่ในหน้าเว็บหลังยืนยันตัวตน

1. ให้ owner สร้าง/แก้ API key ของแท็บเล็ตให้มี scope `reports:profit` (ไม่มี = `DY403`) · ควรเห็นปุ่มนี้เฉพาะ owner ตามที่ POS ตัดสินเอง (สิทธิ์จริงของ dayo วัดที่ key ไม่ใช่ตัวผู้ใช้)
2. เมื่อกดปุ่ม ยิง (ไม่ต้องมี body, **ไม่ใช้** `Idempotency-Key`, ไม่ต้องแนบ staff_id):
```
POST https://<โดเมนร้าน>/api/v1/pos/profit-view
Authorization: Bearer dayo_<hex64>
```
3. คำตอบสำเร็จ (200):
```json
{ "ok": true, "data": {
  "request_id": "b6f0…", "url": "https://<โดเมนร้าน>/profit-view/b6f0…",
  "method": "otp", "expires_at": "2026-09-26T10:05:00+00:00" } }
```
   `expires_at` = อายุของ **ลิงก์ ~5 นาที** (นับจากขอ) ถ้าเลยต้องขอใหม่
4. เปิด `data.url` ใน **เบราว์เซอร์ปกติ / แท็บใหม่ / Custom Tab** (ห้าม iframe · WebView ที่ฝังในแอปอาจใช้ได้หรือไม่ขึ้นกับ POS — แนะนำเปิดนอก) แล้วแสดงข้อความตาม `method`:
   - `otp` — "ส่งรหัส 6 หลักทาง LINE ให้เจ้าของแล้ว กรอกในหน้าที่เปิด"
   - `code` — "กรอก 'รหัสดูกำไร' ที่เจ้าของตั้งไว้" (เกิดเมื่อไม่มีผู้รับ OTP หรือบอทส่ง OTP ไม่สำเร็จ — dayo ตกไปใช้รหัสเองอัตโนมัติ)
   - `none` — owner ยังไม่ได้ตั้งผู้รับ OTP/รหัส · หน้าเว็บจะบอกให้ไปตั้งค่า (POS แจ้งผู้ใช้สั้น ๆ ได้ ไม่ต้องกรอกอะไร)
5. หลังผู้ใช้ยืนยันในหน้าเว็บ dayo ออก session **15 นาที** (คุกกี้ในเบราว์เซอร์นั้น) POS ไม่เห็น/ไม่ได้รับอะไรกลับ — ไม่มี callback ไม่ต้อง poll หมดเวลาแล้วกดปุ่มใหม่
6. **อย่า** cache/บันทึก `url` หรือ `request_id` นาน · **อย่า** log ค่าใน URL ลง log ที่ส่งออก

### Error handling (รูปเดียวกับ API อื่น `{ok:false,error:{code,message}}`)
| HTTP | code | สาเหตุ | POS ทำ |
|---|---|---|---|
| 401 | `DY401` | key ผิด/ถูกปิด | แจ้ง "ตั้งค่าคีย์ใหม่" ไม่ retry |
| 403 | `DY403` | key ไม่มี `reports:profit` | แจ้งให้ owner เปิด scope |
| 429 | `DY429` | (ก) เครื่องถูกล็อก 15 นาทีเพราะกรอกรหัส/OTP ผิด 5 ครั้งใน 15 นาที (ข) เครื่องนี้ขอเกิน 20 ครั้ง/ชม. (ค) ร้านขอ OTP เกิน 5 ครั้ง/ชม. (ง) ร้านขอ OTP ครบ 20 ครั้ง/วันไทย |
| 5xx / เครือข่าย | — | ชั่วคราว | แจ้งลองใหม่ · ห้าม retry อัตโนมัติวนรัว (จะกินโควตาข้อ ค/ง) |

ตอน `DY429`: อ่านวินาทีที่ต้องรอจาก **header `Retry-After`** (ฟิลด์ `retry_after` ใน JSON body **ไม่มี** — อย่าอ่านจาก body) แสดง "ลองใหม่ได้ในอีก N นาที" · กรณี (ง) `Retry-After` = วินาทีถึงเที่ยงคืนไทย (อาจหลายชั่วโมง)
โควตากินทุกครั้งที่ขอสำเร็จ (แม้ผู้ใช้ปิดหน้าไปเฉย ๆ) → **debounce ปุ่ม** (เช่น disable 10–30 วิ หลังกด) และห้ามกดซ้ำเมื่อลิงก์เดิมยังไม่หมดอายุ (เก็บ `url` ไว้ในหน่วยความจำจนถึง `expires_at` แล้วเปิดซ้ำได้)
ทุกคำตอบใต้ `/api/v1` รวม 429 มีหัว CORS ตาม `POS_ORIGINS` เหมือนเดิม · rate limit ทั่วไป 60 คำขอ/นาที/key ยังใช้ด้วย

## 3. สิ่งที่คงเดิม
- `/v1/pos/catalog`, `/v1/pos/push` (สัญญาเดิมทุกข้อ, ไม่ใช้ `Idempotency-Key`), CORS/`POS_ORIGINS`, กติกาว่า API ไม่ส่งต้นทุน/กำไร, บิล POS แก้/ยกเลิกเฉพาะ owner บนเว็บ dayo
- ไฟล์ตัวคิดราคา + `pos-parity.json` + `pricing.files_sha256` ในแคตตาล็อก (ค่าตามข้อ 1)
- ไม่มีการเปลี่ยนใน catalog/push เพราะ ADR-0055 ยกเว้นที่ scope ใหม่

## 4. เงื่อนไขเปิด `/api/v1` (อัปเดต)
1. ทดสอบเชื่อมจริงผ่าน (รวมปุ่มดูกำไรถ้าจะใช้)
2. ตั้ง `POS_ORIGINS` = origin production ของแท็บเล็ตตรงตัว
3. สร้าง API key แท็บเล็ต: `catalog:read, staff:read, orders:read, orders:write` (+ `reports:profit` **เฉพาะเมื่อจะใช้ปุ่มดูกำไร**) · ก่อนใช้ปุ่ม owner ต้องตั้งวิธียืนยัน (ผู้รับ OTP ทาง LINE หรือ รหัสดูกำไร) ในตั้งค่า
4. เจ้าของสำรองข้อมูลภายใน 24 ชม. ก่อนเปิด + ซ้อมกู้ลงโปรเจกต์ test 1 ครั้ง
5. เจ้าของตั้ง `API_V1_ENABLED=1` เอง (ทีม POS/agent ห้ามเปิด) · ระหว่างพัฒนาใช้ test/local (`POS_ORIGINS=http://localhost:5173`)

## 5. เรื่องค้างที่ทีม POS ต้องตอบ/ทำ
- ยืนยันวิธีเปิด `url` (แท็บใหม่/Custom Tab) ที่ใช้ได้จริงบนแท็บเล็ตของร้าน — ฝัง iframe ไม่ได้
- ออกแบบ UX ปุ่ม: debounce, นับถอยหลัง `Retry-After`, ข้อความ 3 แบบตาม `method`
- ตัดสินว่าแสดงปุ่มให้ใครบ้างบนแท็บเล็ต (dayo ไม่ตรวจตัวผู้ใช้ ตรวจแค่ key)
- vendor:update: ไม่ต้อง (ไฟล์ตัวคิดราคาไม่เปลี่ยน) แต่ให้ยืนยันว่า POS ยังตรง `files_sha256` ข้างบน
- D66 สั่งล่วงหน้า (ลูกค้า OA) = เฟส ข ยังไม่มีสเปก ต้องนัดคุย
- P3 กะ/ลิ้นชัก ยังเลื่อน: `shift_id` ส่ง `null` ได้ต่อไป
