# ทบทวนโมเดลของทีม agent (30 ก.ย. 2569)

ที่มา: เจ้าของสั่งให้ดูว่า agent ตัวไหนลดโมเดลได้เพื่อประหยัด token โดยไม่เสียคุณภาพ · ผลบันทึกเป็น D137

## งานที่เหลือของโปรเจกต์ (ใช้ตัดสินว่าต้องเก่งแค่ไหน)

- **Task 19:** แก้ fixture ตามรายงาน dayo และเทียบ parity กับ dayo จริง เป็นงานเงินและงานส่งข้อมูล
- **แผนถัดไป:** ค่าใช้จ่าย ตอกบัตร เงินเดือน รายงาน สำรองข้อมูล และ deploy
  - ค่าใช้จ่ายกับเงินเดือนเป็นสูตรเงินใหม่
  - ตอกบัตรกับค่าใช้จ่ายต้องส่งขึ้น dayo แบบกันซ้ำ ใช้รูปแบบ outbox เดิม
- **หน้าจอ:** เป็นงานตามสเปก มีเทสต์และ e2e คุม

## ที่ประหยัดได้จริงมากกว่าการลดรุ่นในไฟล์

ไฟล์ agent กำหนดรุ่น "ปกติ" · หัวหน้าทีมระบุรุ่นเองได้ทุกครั้งที่สั่งงาน ข้อเหล่านี้ประหยัดได้มากกว่า:

1. **สั่งรุ่นให้ตรงงานทุกครั้ง** · ไม่ระบุ = ได้รุ่นของไฟล์ agent
2. **รวมงานเล็กแบบเดียวกันเป็นคำสั่งเดียว** (เช่นแก้ fixture หลายไฟล์) แทนการเรียก agent ต่อไฟล์
3. **ตรวจซ้ำหลังแก้ใช้ Sonnet** · Opus ใช้เฉพาะตรวจทั้งสายก่อน merge
4. **log ยาวให้ `test-runner` อ่าน** ไม่ให้ไหลเข้าเซสชันหลัก
