# สั่งซื้อผ่าน LINE OA ต่อกับ API ของ POS

สถานะ: ตรวจจากเอกสารทางการ 17 ก.ย. 2026 (✅ อ่านวันนี้ · ⚠️ จากความรู้เดิม)
บริบท: เจ้าของต้องการให้ลูกค้าสั่งผ่าน LINE ได้ (D25) โดยต่อกับ API ของ POS ไม่ใช่บอทเขียน Excel แบบเดิม · ข้อจำกัด: **ไม่ผูกบัตร ไม่มีค่าใช้จ่ายรายเดือน** (D15)

---

## 1. ข้อเท็จจริงที่กำหนดการออกแบบ

| เรื่อง | ข้อเท็จจริง | ผล |
|---|---|---|
| ราคา LINE OA ไทย ✅ | Free ฿0 = **300 ข้อความ/เดือน** · Basic ฿1,280 = 15,000 · Pro ฿1,780 = 35,000 (ไม่รวม VAT) | ข้อความที่ "ร้านส่งหาลูกค้าเอง" (push) มีโควตาแค่ 300/เดือน ≈ 10/วัน |
| Reply message ✅ | "reply messages are not counted towards the message count" — ตอบกลับภายในโอกาสที่ลูกค้าทักมา **ฟรีไม่จำกัด** | ต้องออกแบบให้ทุกการโต้ตอบเป็น reply ไม่ใช่ push |
| Reply token ⚠️ | ใช้ได้ครั้งเดียว และต้องใช้ภายในเวลาสั้น (เอกสารเคยระบุ ~1 นาที ปัจจุบันไม่ระบุตัวเลข) | เซิร์ฟเวอร์ที่ตอบช้า 30–60 วินาที (cold start) จะตอบไม่ทัน |
| Webhook ✅ | LINE แนะนำให้ตอบ 2xx เร็วแล้วประมวลผลแบบ async · ถ้าไม่ตอบ 2xx จะ redeliver "จำนวนครั้ง/ช่วงเวลาไม่เปิดเผย" และ "ไม่รับประกันว่าจะส่งถึง" | endpoint ต้อง **ตื่นอยู่ตลอด** |
| LIFF ✅ | เว็บแอปที่เปิดในแอป LINE (`https://liff.line.me/{liffId}` หรือปุ่ม rich menu) · ได้ `userId` และ ID token · ไม่มีค่าใช้จ่าย ⚠️ (ไม่มีหน้าราคาเพราะเป็นส่วนของ LINE Login ฟรี) | ลูกค้าสั่งผ่านหน้าเว็บของเราเองได้ **โดยไม่ต้องส่งข้อความเลย** |
| ตรวจตัวตนฝั่งเซิร์ฟเวอร์ ✅ | `POST https://api.line.me/oauth2/v2.1/verify` ด้วย `id_token` + `client_id` → ได้ `sub` (userId), `name`, `picture` | API ของ POS รู้ว่าใครสั่ง โดยไม่ต้องมีระบบสมัครสมาชิก |
| Render free ✅ | หลับหลังไม่มี request 15 นาที · ตื่นใช้เวลา ~1 นาที · 750 ชม./เดือน (เดือน 31 วัน = 744 ชม.) · ไม่ได้ห้ามการ ping เพื่อกันหลับ (แต่ก็ไม่ได้อนุญาตชัดเจน) · มี region Singapore | เปิดตลอดได้ **1 service** ถ้ามีตัว ping ทุก ≤ 14 นาที |

## 2. ทางเลือกรูปแบบการสั่ง

| แบบ | วิธี | ข้อดี | ข้อเสีย | ข้อความที่ใช้ |
|---|---|---|---|---|
| **A. LIFF สั่งเอง** ⭐ | ลูกค้ากด rich menu → เปิดหน้าเมนูของเรา (PWA เดียวกับ POS แต่โหมดลูกค้า) → เลือกเมนู/ขนาด/ความหวาน → จ่าย QR → ดูสถานะในหน้าเดิม | UI เต็ม ตรวจสอบง่าย ไม่กินโควตาข้อความเลย ใช้ `packages/domain` ชุดเดียวคำนวณราคา | ต้องตั้ง LINE Login channel + LIFF · ลูกค้าต้องเปิดหน้าเว็บ (ในแอป LINE) | 0 (สถานะดูใน LIFF) · push "พร้อมรับ" เป็นตัวเลือก |
| B. บอทแชท | ลูกค้าพิมพ์ "ชาไทย 20 50" → บอทตอบ quick reply ยืนยัน | ไม่ต้องเปิดหน้าเว็บ | parser ภาษาไทยผิดง่าย · ทุกขั้นเป็น reply ต้องตอบทันที (Render หลับ = พัง) · ไม่มีที่แสดง QR สวย ๆ | 0 (reply) แต่เสี่ยง token หมดอายุ |
| C. บอทเจ้าของบันทึกขาย (ตาม Schema ในไฟล์ Excel) | เจ้าของพิมพ์ "ขาย ชาเขียว 22 100% 3" | — | POS แทนที่หมดแล้ว ไม่จำเป็น | — |

**แนะนำ A** และคง B ไว้เป็น "คำสั่งลัด" 2–3 คำในอนาคต (เช่น พิมพ์ "เมนู" → reply ลิงก์ LIFF)

## 3. สถาปัตยกรรมที่เข้ากับข้อจำกัดฟรี

```
ลูกค้า (แอป LINE)
  │ rich menu → LIFF URL
  ▼
apps/pos โหมดลูกค้า (Cloudflare Pages)  ── liff.init → ID token
  │ POST /line/orders  (ID token → verify กับ LINE → userId)
  ▼
apps/api บน Render Singapore (NestJS)  ── ตื่นตลอดด้วย ping ทุก 10 นาที (cron-job.org / UptimeRobot ฟรี ⚠️)
  │  · /health ไม่แตะ DB (Neon ยังหลับได้)
  │  · /line/webhook ตอบ 200 ทันที แล้วประมวลผล async
  │  · เก็บ "มีออเดอร์ใหม่" ไว้ในหน่วยความจำ → แท็บเล็ต poll ถูก ๆ
  ▼
Neon (Postgres)  ── ออเดอร์ LINE ถูกสร้าง "ที่เซิร์ฟเวอร์" (origin = server)
  │
  ▼ pull ทุก 30–60 วิ ขณะเปิดกะ
แท็บเล็ต POS  ── รับ/ยืนยันเงิน/ทำ/พร้อมรับ → event push ขึ้นตามปกติ
```

ข้อควรระวัง
- Render ฟรีเปิดตลอดได้ **service เดียว** (744/750 ชม.) → API กับ webhook ต้องอยู่ใน NestJS app เดียวกัน
- Neon ยังต้องหลับได้: endpoint ที่ถูก ping และ endpoint poll ของแท็บเล็ตต้องเช็ค flag ในหน่วยความจำก่อนแตะ DB
- Render อาจ restart ได้ทุกเมื่อ (deploy, maintenance) → flag ในหน่วยความจำหายได้ → แท็บเล็ตต้อง pull จริงจาก DB อย่างน้อยทุก 5 นาทีเป็น fallback
- ถ้าวันหนึ่ง Render เปลี่ยนนโยบายห้าม ping → ทางออกฟรีที่ไม่ผูกบัตรสำหรับ webhook คือ **Cloudflare Workers** (100k req/วัน ตื่นตลอด) รับ webhook แล้วส่งต่อ · หรือ **Supabase Edge Functions** (500k invocations/เดือน) — ทั้งคู่ไม่ใช่ NestJS แต่โค้ดส่วน webhook เล็กมาก

## 4. โฟลว์ออเดอร์ LINE (ข้อเสนอ)

| ขั้น | ใคร | ระบบทำอะไร | สถานะออเดอร์ |
|---|---|---|---|
| 1 | ลูกค้า | เปิด LIFF เลือกเมนู → กด "สั่ง" | `PENDING_PAYMENT` (สร้างที่เซิร์ฟเวอร์, channel = LINE OA, ยังไม่มี receipt_no, ยังไม่ตัดสต็อก) |
| 2 | ลูกค้า | เห็น QR PromptPay ยอดตรงบิล · โอน · กด "โอนแล้ว" (+ แนบสลิปได้ เฟส 2 ตรวจอัตโนมัติ) | `PENDING_VERIFY` |
| 3 | ร้าน (แท็บเล็ต) | มีแถบ "ออเดอร์ LINE" เด้ง · ดูยอดในแอปธนาคาร · กด "รับเงินแล้ว" → **ได้ receipt_no · ตัดสต็อก · เข้าคิว** (เหมือนบิลหน้าร้านทุกอย่าง) | `PAID` |
| 4 | ร้าน | ทำเสร็จ กด "พร้อมรับ" | `READY` → (ตัวเลือก) push 1 ข้อความ "พร้อมรับแล้ว คิว 17" |
| 5 | ลูกค้า | มารับ ร้านกด "รับแล้ว" | `PICKED_UP` |
| ยกเลิก | ระบบ | `PENDING_PAYMENT` เกิน 15 นาที → ยกเลิกอัตโนมัติ (ไม่กระทบสต็อก) · ร้านปฏิเสธได้พร้อมเหตุผล (ของหมด) → ถ้าจ่ายแล้วบันทึกโอนคืน | `CANCELLED` / `REJECTED` |

หลักที่ยังคงอยู่: **สต็อกตัดและเลขที่บิลออกที่แท็บเล็ตตอน PAID เท่านั้น** (ตรงกับ D18) · เซิร์ฟเวอร์เป็นแค่ "ต้นทาง" ของออเดอร์ ไม่ใช่ผู้ตัดสิน

งบข้อความ: ถ้าเปิด push "พร้อมรับ" = 1 ข้อความ/ออเดอร์ → 300/เดือน ≈ 10 ออเดอร์ LINE/วัน · เกินแล้ว LINE จะไม่ส่ง (ไม่คิดเงินเพิ่มในแผนฟรี) → ระบบต้องนับโควตาเองและปิด push อัตโนมัติเมื่อใกล้เต็ม · ลูกค้ายังดูสถานะใน LIFF ได้เสมอ

## 5. สิ่งที่ต้องตั้งค่า (ฟรีทั้งหมด)

1. LINE Official Account (มีอยู่แล้วหรือสร้างใหม่) แผน Free
2. LINE Developers: Provider → **Messaging API channel** (webhook, channel secret, access token) + **LINE Login channel** (LIFF, `openid` scope)
3. LIFF app ชี้ไปที่ URL ของ PWA โหมดลูกค้า (Cloudflare Pages) · ใส่ปุ่มใน rich menu
4. ตัว ping ฟรี (cron-job.org หรือ UptimeRobot ⚠️) ยิง `/health` ทุก 10 นาที
5. `.env` บน Render: `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_LOGIN_CHANNEL_ID`

## 6. ความเสี่ยงและข้อกฎหมาย

- **ข้อมูลส่วนบุคคล (PDPA)**: เก็บแค่ `line_user_id` + ชื่อที่แสดง · ไม่เก็บเบอร์/ที่อยู่ (รับที่ร้านเท่านั้น) · มีข้อความแจ้งวัตถุประสงค์ในหน้า LIFF ครั้งแรก ⚠️
- **สั่งแล้วไม่มา**: บังคับจ่ายก่อนทำ (ขั้น 3) → ไม่มีของเสีย
- **โอนปลอม/สลิปปลอม**: ร้านดูยอดจริงในแอปธนาคารก่อนกด "รับเงินแล้ว" · เฟส 2 ต่อ SlipOK
- **Render ping**: เป็นพื้นที่สีเทา ถ้าถูกระงับ → ย้าย webhook ไป Cloudflare Workers ตาม §3
- **เวลาทำการ**: LIFF ต้องรู้ว่าร้านเปิดอยู่ไหม (มี shift เปิด + ไม่ได้กด "หยุดรับออเดอร์ LINE") ไม่งั้นลูกค้าสั่งแล้วไม่มีคนทำ
