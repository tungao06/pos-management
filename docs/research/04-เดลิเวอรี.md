## 2. ⭐ API — คำตอบต่างกันสุดขั้วระหว่าง Grab กับ LINE MAN

### GrabFood: มี API สาธารณะจริง ✅

- **เอกสาร:** https://developer.grab.com/docs/grabfood/ (อยู่ในหน้าเดียวกับ Express, GrabMart, GrabMall, POS API v3, GrabPay)
- **Base URL:** `https://partner-api.grab.com` · sandbox `https://partner-api.grab.com/grabfood-sandbox`
- **Auth:** OAuth 2.0 client-credentials, scope `food.partner_api` ใช้ `partner_id` / `partner_secret` / `client_id` / `client_secret`
- **SDK ทางการบน GitHub ยัง maintain อยู่:**
  - Go — https://pkg.go.dev/github.com/grab/grabfood-api-sdk-go — **v1.0.4 เผยแพร่ 20 ก.ค. 2026** (ปัจจุบัน)
  - Python — https://github.com/grab/grabfood-api-sdk-python (API v1.1.3)
  - Node — https://github.com/grab/grabfood-api-sdk-node
  - Java — https://github.com/grab/grabfood-api-sdk-java
- **ความสามารถ:** รับ/ปฏิเสธออเดอร์, ยกเลิก, แก้ไข, mark-ready, คืนเงิน, ดึงรายการออเดอร์ · อัปเดตเมนู + batch update + ติดตามสถานะ sync + push notification · **พักร้าน (pause store)** · สถานะ/เวลาเปิด-ปิดร้าน · เวลาส่งและเวลาทำอาหารโดยประมาณ · จัดการแคมเปญ (CRUD) · QR/voucher สำหรับ dine-in · **"POS order sync"** · แจ้งเตือนสมาชิก · **webhook สำหรับ order lifecycle**

⚠️ **แต่ต้องได้รับอนุมัติ** — developer.grab.com **ไม่มีสมัครเอง** มีแค่ฟอร์ม "Integrate now" credential เป็นแบบ "partner-issued"
**หลักฐานว่า POS ภายนอกเข้าได้จริง:** เอกสารของ StoreHub อธิบายขั้นตอนจริง — ร้านต้องมีบัญชี GrabFood ที่อนุมัติแล้ว จากนั้น **"merchants authorize the connection through Grab's Developer Portal"** แล้ว **Grab ตรวจสอบไม่เกิน 2 วันทำการ** = โมเดล **POS partner ที่ลงทะเบียนแล้ว + ลูกค้าแต่ละร้านยินยอมผ่าน OAuth** ไม่ใช่สมัครเปิด

⚠️ **ไม่มีเกณฑ์คุณสมบัติเผยแพร่เลย** — ไม่มีจำนวนร้านขั้นต่ำ ไม่มี checklist การรับรอง ไม่มีตารางค่าธรรมเนียม คาดว่าจะต้องมี: นิติบุคคลไทย, business case, ผ่าน UAT/certification กับ sandbox, และเซ็นสัญญา partner **Grab ไม่ได้ประกาศระดับ "ร้านเดียว/นักพัฒนาคนเดียว"**
⭐ **ยิงฟอร์ม "Integrate now" ถามตรงๆ ว่ามีระดับ self-integrator สำหรับร้านเดียวไหม** — แย่สุดคือเขาปฏิเสธ เสียเวลาไปหนึ่งสัปดาห์

### LINE MAN Wongnai: ไม่มี API เลย — เลิกคิดเรื่องต่ออัตโนมัติ ✅

- หน้า partner ของ LMWN เสนอแค่ Marketing Solutions, Merchant Services และ **"POS Solutions"** = **ขาย POS ของตัวเอง ไม่ใช่ให้ API ต่อ POS เรา** ทางเดียวคืออีเมล `partnership@lmwn.com`
- หน้า "Be Our Partner" ระบุผลิตภัณฑ์ใต้หมวด POS ไว้ 2 อย่างพอดี: **Wongnai POS และ FoodStory POS** — ของตัวเองทั้งคู่

**หลักฐานชี้ขาด 3 ชิ้น:**
1. **LMWN ซื้อ FoodStory POS ไป (2023) แต่การเชื่อม LINE MAN เข้า FoodStory POS ยังต้องให้พนักงาน LMWN ทำด้วยมือ ใช้เวลา 5–7 วันทำการ** — ร้านต้องลงทะเบียนผ่าน WMA สร้างช่องทางขาย LINE MAN ใน owner portal ของ FoodStory แล้วรอเจ้าหน้าที่
2. **การรับออเดอร์ LINE MAN เป็นฟีเจอร์ที่ต้องจ่ายเงิน (Wongnai POS Subscription)** ไม่มีในแอป Wongnai Merchant App ที่ให้ฟรี
3. ⭐ **StoreHub — บริษัท POS ระดับภูมิภาคที่มีเงินทุน — ระบุตรงๆ ในเอกสารตัวเองว่า "LINEMAN Orders (Thailand Only)" ต้อง MANUAL ENTRY** *"for services like LINEMAN, orders must be accepted on their platform and then manually entered into your StoreHub POS, as these do not directly integrate"*

**ถ้า StoreHub เอา API ของ LMWN ไม่ได้ เราก็ไม่ได้**
คำกล่าวอ้างว่า "LMWN เปิด API ให้ระบบ custom" พบเฉพาะในคอนเทนต์การตลาดของบุคคลที่สาม (เช่น klikit) **ไม่มี endpoint ไม่มี auth ไม่มีเอกสารอ้างอิง** → ถือว่าไม่มีมูล

**สรุป: LINE MAN เป็นกำแพงเชิงพาณิชย์ ไม่ใช่เชิงเทคนิค คำตอบที่เขาตั้งใจให้คือ "ซื้อ Wongnai POS / FoodStory POS สิ"**

### ShopeeFood ⚠️ (โน้มเอียงไปทางไม่มี)
StoreHub ระบุว่ามี integration ใช้เวลา onboarding 3–7 วันทำการ และ klikit อ้างว่าครอบคลุม ShopeeFood ในภูมิภาค → **มีช่องทาง partner บางอย่างอยู่** แต่**ไม่พบเอกสาร merchant/open platform API ของ ShopeeFood สำหรับประเทศไทยเลย** สมมติว่าเป็น partner-gated เป็นอย่างน้อย และด้วยส่วนแบ่งที่เล็ก **ไม่คุ้มไล่ตาม**

## 4. Aggregator / middleware — ไทยแทบไม่มีใครครอบคลุม

- **Deliverect** — หน้า Grab Food ของเขาระบุ **Global / Hong Kong / Singapore เท่านั้น ไม่มีไทย** ไม่มี LINE MAN / ShopeeFood / Robinhood
- **klikit** (สิงคโปร์/APAC เป็นตัวเลือกที่น่าจะครอบคลุมไทยที่สุด) — อ้างว่ามี ฟิลิปปินส์ อินโดนีเซีย สิงคโปร์ มาเลเซีย ญี่ปุ่น **ไทย** integration ที่ระบุ: Grab, Gojek, Uber Eats, ShopeeFood, Baemin, Demae-can **เริ่มต้น US$25/เดือน ไม่มีค่าต่อออเดอร์** ⚠️ **แต่บทความเปรียบเทียบของเขาเองไม่ได้ระบุ LINE MAN Wongnai หรือ Robinhood** ทั้งที่มีหน้าการตลาดแยกที่บอกเป็นนัยว่ารองรับ LMWN — ความขัดแย้งนี้บอกว่าหน้า LMWN นั้นเป็นความหวัง ไม่ใช่ความจริง
- **Otter / ChownNow / Lunchbox / Square** — เน้นสหรัฐฯ "รองรับแพลตฟอร์มเอเชียได้จำกัด"
- **UrbanPiper / Hubster** — ไม่พบหลักฐานเรื่องไทยเลย

⭐ **สรุป: แม้แต่ aggregator ก็เอา LINE MAN ให้เราไม่ได้** middleware แก้ได้แค่ GrabFood ซึ่ง Grab API ก็แก้ให้อยู่แล้วโดยตรง

## 5. ค่า GP (Gross Profit / ค่าคอมมิชชั่น)

### อัตราปกติ
| แพลตฟอร์ม | GP (ไม่รวม VAT) | รวม VAT 7% ของค่า GP |
|---|---|---|
| **GrabFood** | 30% (บล็อกของ Grab เองเขียนว่า 30–35%) | ~32.1% |
| **LINE MAN** | 30% | ~32.1% |
| **ShopeeFood** | 32% | ~34.2% |
| **Robinhood** | 28% | ~30% |
| *(foodpanda เดิม 32% — ปิดแล้ว)* | | |

**กลไก VAT:** 7% คิดจาก**ค่าคอมมิชชั่นของแพลตฟอร์ม** ไม่ใช่จากยอดขายรวม → GP 30% = 30% + (30% × 7%) = **หัก 32.1%**
**Grab จ่ายเงินให้ร้านวันทำการถัดไป** (ออเดอร์เสร็จ 15 ม.ค. 23:59 → จ่าย 16 ม.ค.) ผ่าน KBank/KTB/BBL

### ⚠️ ตอนนี้เป็นช่วงสงครามราคา — เรตต่ำกว่าปกติมาก
โครงการ **คนละครึ่งพลัส** (ลงทะเบียนตั้งแต่ 3 พ.ย. 2568) จุดชนวนสงครามราคา ร้านค้าเข้าร่วมได้แพลตฟอร์มเดียวเท่านั้น:
- **Grab: GP ลดเหลือ 7%** (ลงทะเบียน 3 พ.ย. 2568) หรือ **9%** ในภายหลัง
- **LINE MAN:** ลดพิเศษไม่ระบุตัวเลข และแยกลด GP ของโครงการไทยช่วยไทยพลัส **จาก 15% เหลือ 10%**
- **ShopeeFood: 13%** ในโครงการ พร้อม "GP พิเศษ" กับทุกออเดอร์คนละครึ่งพลัส
- **Robinhood:** ครึ่งหนึ่งของ GP ปกติสำหรับร้านเดิม **15% สำหรับร้านใหม่ 90 วัน**

**และตอนนี้ GrabFood ยังแจก GP 0% 30 วัน สำหรับร้านใหม่ที่ลงทะเบียนด้วยโค้ด `GP0` ใช้ได้ 1 ม.ค. – 31 ธ.ค. 2026**

⭐ **ห้าม hard-code ค่า GP** — ทุกแหล่งย้ำว่าเป็นเรื่องของสัญญา ไม่ใช่ราคากลาง (*"ค่า GP เป็นเรื่องของสัญญา ไม่ใช่ราคากลาง"*) ร้าน 2 ร้านในตึกเดียวกันอาจจ่ายไม่เท่ากัน ขึ้นกับประเภทร้าน แพ็กเกจ โปรโมชั่นตอนสมัคร และการเจรจา
→ **เก็บเป็น config ต่อช่องทาง + มีวันที่มีผล และกระทบยอดกับรายงาน settlement ของแพลตฟอร์ม ไม่ใช่คำนวณเอง**

## 6. ⭐ กฎระเบียบ กขค. — กำลังจะบังคับใช้เดือนนี้ ✅

**20 ส.ค. 2026 คณะกรรมการการแข่งขันทางการค้า (กขค./TCCT) อนุมัติ "แนวปฏิบัติมาตรฐานสำหรับแพลตฟอร์มดิจิทัลบริการเรียกรถและส่งของตามสั่ง"**

- **ห้ามเก็บค่า GP ค่าโฆษณา และค่าส่งเสริมการขายที่ไม่เป็นธรรม**
- **ห้ามผูกขาดช่องทางเดียว (exclusive dealing)**
- ⭐ **ห้ามบังคับให้ราคาเท่ากันทุกช่องทาง (rate parity)**
- **ห้าม dark pattern และการเอื้อประโยชน์ตัวเอง (self-preferencing)**
- ต้องเปิดเผยค่าธรรมเนียมอย่างโปร่งใส
- รับฟังความเห็น 20–31 ส.ค. 2026 · **คาดเริ่มบังคับใช้กันยายน 2026 (= เดือนนี้)**
- ที่มา: มีเรื่องร้องเรียน 17 เรื่อง · ตลาด ~45,000 ล้านบาท (2025) · ไรเดอร์ 400,000+ คน · **เหลือผู้ประกอบการรายใหญ่ 2 ราย**

⭐ **ข้อห้าม rate parity มีผลตรงกับเรา: ตั้งราคาบนแอปแพงกว่าหน้าร้านได้อย่างถูกกฎหมาย**
คิดเลข: GP 32% → ขาย **65 บาท** บนแอปเหลือ **44 บาท** ซึ่ง**น้อยกว่า**ขายหน้าร้าน **55 บาท** → ถ้าไม่บวกราคาขึ้น ยิ่งขายเดลิเวอรียิ่งขาดทุน
**นี่คือข้อได้เปรียบใหญ่ที่สุดของการมี POS เอง และเป็นสิ่งที่จ่ายค่าโปรเจกต์ทั้งหมดคืนได้เร็วกว่า integration ใดๆ**

## 7. แผนที่แนะนำสำหรับ POS ที่สร้างเอง

1. ⭐ **ทำ "ช่องทางขาย" (channel) เป็นพลเมืองชั้นหนึ่งใน schema ตั้งแต่วันแรก**
   `channel` (หน้าร้าน / Grab / LINE MAN / ShopeeFood / Robinhood), `gross`, `gp_rate` (มีวันที่มีผล), `vat_on_gp`, `net_payout`, `settlement_date`, `platform_order_ref`
   **การมาเพิ่มทีหลังเจ็บปวดมาก**
2. ⭐ **ทำหน้าคีย์ออเดอร์เดลิเวอรีเร็วๆ** — ปุ่ม "ออเดอร์ LINE MAN" ที่เลือก channel ให้อัตโนมัติ แสดงเฉพาะเมนูขายดี ~15 ตัวเป็นปุ่มใหญ่ และเก็บเลขออเดอร์ของแพลตฟอร์ม **เป้าหมายต่ำกว่า 10 วินาที**
   → **นี่คือสิ่งที่คุ้มค่าที่สุดที่สร้างได้ และใช้ได้วันแรกกับทุกแพลตฟอร์ม** (ร้านน้ำเมนูสั้น คีย์มือ 15–30 วินาที/ออเดอร์ ยอมรับได้จริง)
3. ⭐ **กระทบยอดรายวันจากรายงาน settlement ไม่ใช่ sync รายออเดอร์** — นำเข้ารายงานการจ่ายเงินรายวันของแต่ละแพลตฟอร์ม (CSV/export จาก portal) แล้วจับคู่ยอดรวม → ได้ margin และ COGS แม่นยำโดยไม่ต้องมี API เลย **สำหรับร้านน้ำ วิธีนี้ให้คุณค่าทางธุรกิจ ~90% ของ integration เต็มรูป**
4. **ยิงฟอร์มขอ Grab partner API คู่ขนานไป** — ถ้าได้ ค่อยพัฒนากับ sandbox: order webhook เข้า POS + sync เมนู/ราคา + **พักร้านจาก POS ตัวเอง** (มีประโยชน์มากตอนคิวล้นหรือวัตถุดิบหมด) ถือเป็นกำไร ไม่ใช่สิ่งที่ต้องพึ่ง
5. ⭐ **ตั้งราคาแยกตามช่องทาง** — ด้วย GP ~32% เครื่องดื่ม 65 บาทเหลือ ~44 บาท และข้อห้าม rate parity ของ กขค. (คาดบังคับใช้ ก.ย. 2026) คุ้มครองสิทธิ์ในการบวกราคาบนแอปเพื่อดูดซับ GP
6. 🚫 **ห้ามทำ accessibility-service scraping แอป GrabMerchant / WMA** — พังทุกครั้งที่แอปอัปเดต ผิด ToS ของทั้งสองแพลตฟอร์ม (เสี่ยงโดนระงับบัญชี = เสียรายได้จริง) Play Store ปฏิเสธการใช้ accessibility service ในทางที่ผิด และเราต้องบำรุงรักษาเองตลอดไป **แลกกับการประหยัดแค่ 15 วินาที ไม่คุ้มกับการเสียบัญชี LINE MAN**

## 8. สรุปหนึ่งบรรทัด
**GrabFood มี API จริงที่มีเอกสาร มี SDK และควรลองขอ · LINE MAN ไม่มีและขาย POS ของตัวเองแทน · aggregator ไม่ครอบคลุมไทยอย่างมีนัยสำคัญ → สร้าง POS ที่รู้จักช่องทางขาย + คีย์มือเร็วๆ + กระทบยอดรายวันจาก settlement และถือว่า Grab API เป็นกำไรพิเศษ ไม่ใช่สิ่งที่ต้องพึ่ง**
